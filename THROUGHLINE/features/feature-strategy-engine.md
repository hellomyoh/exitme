# Feature: RAVG v2 전략 엔진 (일일 시그널 · 주문표)

## 1. 목적

확정된 매매 전략 RAVG v2([정본](../SOURCES/trade_algorithm_final.md), [ADR-006](../adr/006-ravg-v2-adoption.md))를 매일 장 마감 후 자동 실행해,
다음 거래일의 지정가 주문표와 계산 근거를 사용자에게 제시한다. 본 프로젝트의 차별점.

## 2. 범위

### 포함 범위

- 일일 시그널 배치: 지표 계산 → 레짐 판정 → 노출 E → 배분 → 주문표 생성·저장
- 주문표 화면(`/signals/daily`): 레짐·목표 노출·주문 목록·조건부 지시문·계산 근거
- 전략 모듈 `strategy/` 패키지 (백테스트와 공유 — [ADR-005](../adr/005-strategy-single-source.md))

### 제외 범위

- 증권사 실주문 발주(v1 범위 외 — 사용자가 HTS에서 수동 발주)
- 장중 실시간 감시·자동 청산 (조건부 지시문으로 대체, §5.7)
- 파라미터 자동 튜닝 (Phase 4 백테스트에서 수동 수행)

## 3. 사용자 시나리오

장 마감 후 배치 완료 → 사용자가 주문표 화면에서 "오늘 레짐: 상승 / 목표 노출 E=1.12 / 내일 주문: KODEX 200 매수 3단 + 레버리지 전술 1차" 목록과
계산 근거(지표값)를 확인 → HTS에서 수동 발주 → 체결분을 실전매매 메뉴에 등록.

## 4. 최종 합의안

전략 규칙은 정본을 따르되, 정본이 다루지 않는 구현 세부 8건(워밍업·σ_down 하한·전이 우선순위·전술 트랙 지표 종목·
장중 트리거 강등·수량 산출·로트 회계·휴장 처리)을 Multi-Agent 검토로 확정했다. 아래 §5가 확정 결과다.

### 검토 요약 (감사용)

- 참여 Agent: [Backend/Quant Engineer](../personas/backend-engineer.md), [QA](../personas/qa.md) (병렬 서브에이전트 2기)
- 핵심 쟁점과 결론: 장중 트리거(σ20>25%·갭 필터)는 종가 지표로 장중 감시가 불가능 → 전일 확정값 기반 **조건부 지시문**으로 강등, 백테스트는 익일 시가 1회 평가로 통일.
  리밸런싱 밴드를 그리드에 적용하면 매수 영구 정지 구간 발생 → 밴드는 리밸런싱 전용. 익절가 회계는 로트 FIFO 스냅샷으로 확정.
- 남은 쟁점: 워밍업·σ_down 하한 등 수치는 `deferred`(Phase 4 튜닝, §15)
- 검토 로그: [discussion/review-strategy-engine-20260828.md](../discussion/review-strategy-engine-20260828.md)

## 5. 기능 요구사항

### 5.1 지표 계산 (거래일 기준)

- 정본 §3의 지표(MA20/60/200, EMA20, ATR20, σ20, σ_down, σ_ref)를 **거래일 창**으로 계산한다. 거래정지일 봉은 창에서 제외하고 전일값 캐리를 금지한다.
- 거래일 캘린더의 단일 소스는 KRX 캘린더(pykrx 시딩)다.
- **전술 트랙 예외**: 레버리지 눌림목 조건(정본 §7)의 EMA20·ATR20은 **KODEX 레버리지 자체 시계열**로 계산한다. 레짐·E·σ 계열은 KODEX 200 기준을 유지한다.

### 5.2 워밍업 가드

- `min_history = 270 거래일`(MA200 + σ_ref 250일 충족). 미충족 시 레짐 = 중립, E = 0으로 고정하고 주문표는 `INSUFFICIENT_HISTORY` 상태로 발행(주문 0건 + 경고 표시). 부분 주문표 저장 금지.

### 5.3 수치 안전 규칙

- `σ_down_floor = 0.03`(연율): E 계산 전 σ_down·σ_ref에 하한 적용. 계산 결과 NaN/inf 발생 시 배치 실패로 처리(전일 주문표 재사용 금지, 미생성 경고).
- σ_ref 중위값: 250일 표본 짝수 개면 중앙 2값 평균, 250일 미달이면 워밍업 가드(§5.2)가 선행 차단.

### 5.4 레짐 상태 머신

- 정본 §4의 조건식에 다음 평가 순서를 고정한다: ① Bear 진입 ② Bull 진입 ③ 현재 상태의 이탈 → Neutral. 이탈+반대편 진입 동시 충족 시 반대편으로 직행(양방향 대칭).
- 경계 비교는 엄격 부등호: 조건이 등호로 정확히 일치하면 미충족(예: MA20 = MA60×0.98 → Bull 유지).
- 초기 상태(워밍업 직후 첫 평가일)는 Neutral 고정. 전일 상태는 `is_current` 시그널 체인(§7)에서 읽는다.

### 5.5 주문 수량 산출

- 그리드 3단: 잔여예산 `(w_200 목표 − 현재 보유) × 자본`을 **균등 1/3** 분배, 수량은 `floor`.
- **목표 금액은 equity 기준** (2026-08-28 공식 검증 확정): `target_200 = w_200 × equity`, 레버리지 전략 트랙 = `w_LEV × 0.7 × equity` — 실효노출 = E 가 정확히 성립해야 한다. 현금 버퍼 0.5%는 목표를 깎지 않고 **매수 가용 현금에서 예약**(`cash_left = 현금 + 예정 매도대금 − equity×0.5%`)으로만 적용.
- 지정가는 ETF 호가 단위 5원으로 정규화 — 매수 **내림**, 매도 **올림**.
- 목표를 초과하게 되는 단계는 주문을 생성하지 않는다(수량 0 주문 금지). 현재 보유 ≥ 목표면 매수 주문 0건.
- **리밸런싱 밴드 ±5%p는 리밸런싱(축소·재조정) 주문에만 적용**한다. 그리드 신규 매수는 밴드와 무관하게 잔여예산 규칙만 따른다. **레짐 전환일·하락 레짐의 축소, 강제청산 트리거는 밴드 무시**(2026-08-28 검증 C2 — 코드도 일치시킴). 레버리지 **전략 트랙 신규 진입(보유 0)** 도 밴드 예외 — "E>1 충족 시 상시 보유"(정본 §7).
- **E ≤ 1.0 → 레버리지 자동 0** (정본 §5.2): 상승 레짐 유지 중이라도 w_LEV 가 0 이 되면 레버리지 전량 매도(lev_liq). 전술 트랙 이탈(레버리지 종가 ≥ 자체 EMA20)은 w_LEV 값과 무관하게 매 평가일 확인한다 (2026-08-28 검증 C1).
- **매도 이중 계상 금지 (2026-08-28 확정)**: 축소(reduce) 수량을 먼저 확정하고, 익절(tp) 주문은 축소분(FIFO 선점)을 제외한 잔여 보유에만 발행한다 — 한 시점의 매도 주문 합계는 보유를 초과할 수 없다. (축소는 시장가라 반드시 체결되므로 선점이 안전)

### 5.6 매도·익절 회계 (로트 FIFO)

- 포지션은 **로트 단위 FIFO 원장**으로 관리한다.
- 중립 레짐 익절가 = 해당 로트 체결단가 × (1 + **체결일** Grid) — 체결 시점 스냅샷 고정, 매일 재계산 금지.
- 상승 레짐 체결분은 코어로 전환(익절 주문 없음). 상승→중립 전환 시 코어 로트의 익절 기준가 = 전환일 종가 × (1 + 전환일 Grid).

### 5.7 조건부 지시문 (장중 트리거 대체)

- 갭 필터·σ20>25% 강제청산은 장중 감시 대신 **전일 확정값 기반 조건부 지시문**으로 주문표에 사전 명기한다.
- 갭 임계값 판정은 **정확값(close − 1.5×ATR, float)** 으로 한다 — 표시용 원 단위 내림값으로 비교하면 경계 시가에서 판정이 뒤집힌다 (2026-08-28 검증 M4).
  예: "시가 ≤ 68,200원(전일종가 −1.5×ATR)이면 잔여 그리드 전량 취소", "σ20 = 24.1% — 종가 기준 25% 돌파 시 레버리지 청산".
- 백테스트도 동일하게 익일 시가 1회 평가로 처리한다([ADR-005](../adr/005-strategy-single-source.md) 수용 기준).

### 5.8 배치·주문표 발행

- Celery beat이 장 마감 후 시세 수집 완료를 확인하고 실행. 대상일 시세 미확보 시 실행 보류 + 경고.
- 주문표에는 계산 근거(지표값 전체·레짐 판정 조건별 충족 여부·E 산출 과정)를 포함해 열람 가능하게 한다.
- 거래정지 종목은 발주 보류로 표기. 다음 거래일이 휴장이면 그다음 거래일 기준으로 발행.
- 전술 트랙 1·2차 조건 동시 충족 시 전술 예산(w_LEV×30%)을 50:50으로 두 주문 모두 발행.

## 6. 비기능 요구사항

- 배치는 장 마감 후 30분 내 완료([ARCHITECTURE §9](../ARCHITECTURE.md)). 같은 입력에 같은 출력(결정론 — 난수·현재시각 사용 금지).
- 배치 시작/종료/실패를 `batch_runs`와 구조화 로그에 기록([ARCHITECTURE §7](../ARCHITECTURE.md)).

## 7. 데이터 설계

공통 규칙은 [ARCHITECTURE §3](../ARCHITECTURE.md) 참조. 이 기능 고유:

- `signal_snapshots(trade_date, version, is_current, regime, e_target, w_200, w_lev, indicators JSONB, status)` — append-only,
  partial unique index `(trade_date) WHERE is_current`. 상태 머신은 is_current 체인만 참조. 버전 승격 시 해당일 이후 전 구간을 동일 트랜잭션에서 재계산.
- `order_sheets(id, signal_id FK, instrument, side, price, qty, kind[grid1|grid2|grid3|tp|reduce|lev_strat|lev_tact1|lev_tact2], directive JSONB)` — append-only.
- `strategy_params(version, params JSONB, valid_from)` — 정본 §10 파라미터의 버전 관리(절제 플래그 포함).

## 8. API 설계

공통 계약은 [ARCHITECTURE §5](../ARCHITECTURE.md) 참조.

- `GET /signals/daily?date=` — 최신(is_current) 시그널 + 주문표 + 계산 근거. 미생성 시 `status: MISSING|INSUFFICIENT_HISTORY|FAILED`와 사유 반환(조용한 실패 금지).
- `GET /signals/history?from=&to=` — 레짐·E 이력(대시보드 게이지·차트 음영용).

## 9. UI/UX 설계

- 주문표 화면: 상단에 레짐 배지·E 게이지·"모의 계산이며 투자 권유 아님" 고지, 본문에 주문 테이블(구분·종목·가격·수량), 조건부 지시문 카드, 하단 접이식 "계산 근거".
- 숫자는 tabular-nums, 다크 우선([REQUIREMENTS §7](../SOURCES/REQUIREMENTS.md)).

## 12. 테스트 시나리오

### 자동 테스트

- **골든**: G1 그리드 3단 — Close=70,000·ATR/C=2% → Grid 1.5% → 68,950/67,900/66,850 (수치 출처는 [basic_trade.md](../SOURCES/basic_trade.md) §5 예시 — v2 clip 0.8~4.0% 내부값으로 유효, 주석에 출처 명기).
  G2 중립 익절 — 68,950 로트·Grid 1.5% → 69,984.25 → 호가 올림 69,985원. **상승 레짐에서는 익절 주문 0건.**
  G3 배분 3점 — E=0.35/0.90/1.30 → (w_LEV,w_200,현금)=(0,35,65)/(0,90,10)/(30,70,0)%, 각 케이스 w_200+2·w_LEV=E.
- **경계·전이**: 레짐 3×3 전이 전수(직행 포함), 등호 경계 미충족 확인(MA20=MA60×0.98 → Bull 유지, Close=MA200 → 진입·이탈 모두 미충족), 휩쏘 5일 시퀀스 무전이, 갭 필터 경계(−1.5×ATR 정확히 → 발동 / −1.4999 → 미발동), 잔여예산(목표 0.65·보유 0.60 → 1단만 생성), E=1.0 경계(w_LEV=0 ↔ >0), 밴드 5.0%p 미실행/5.1%p 실행·트리거 시 밴드 무시.
- **수치 안전**: 20일 무하락 시계열 → σ_down floor 적용·E 유한, NaN 주입 → 배치 실패 + 주문표 미생성.
- **워밍업**: 269 거래일 → `INSUFFICIENT_HISTORY`·주문 0건, 270 거래일 → 정상 발행.
- **재현성**: 동일 스냅샷 2회 실행 → 주문표 해시 일치. 백테스트 d일 절단 결과와 시그널 배치 d일 결과 바이트 동일([ADR-005](../adr/005-strategy-single-source.md)).
- **호가·수량**: 익절가 5원 올림, 매수가 5원 내림, 수량 floor·잔여예산 합계 미초과, 전술 1·2차 동시 충족 50:50.

### 수동 QA

- 주문표 화면의 계산 근거가 지표값과 일치하는지 표본 검산, 고지 문구 표시, 다크/라이트.

### 예외 케이스

- 시세 미확보일 배치 보류, 거래정지 종목 발주 보류 표기, 휴장 익일 처리, 배치 실패 시 `FAILED` 상태 + 전일 주문표 미재사용.

### 회귀 테스트 영향

- 전략 모듈은 파라미터 튜닝·플래그 변경이 잦음 — 위 골든·경계 전수를 회귀 스위트로 고정([qa/regression-checklist.md](../qa/regression-checklist.md)).
