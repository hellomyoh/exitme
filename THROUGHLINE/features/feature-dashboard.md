# Feature: 자산 대시보드

## 1. 목적

총자산·손익·레짐을 한 화면에서 점진 공개 원칙으로 보여준다. 루프(검증→실행→관리)의 관리 단계.

## 2. 범위

### 포함 범위

- 히어로: 총자산 단일 수치 + 전일대비(금액·%) + 전체 기간 수익률
- 자산 구성 도넛(주식/현금/기타 수동 등록), 보유 종목 테이블, 비중 상위 5·업종 분산
- **자산 내용 카드(2026-09-02)**: 총자산(KRW) + 한국 주식 카드(실전매매 KR 포트 합산 — 평가액·보유원가·평가손익 금액/%) + 미국 주식 카드(**$ 표기**, KRW 총자산 합산 제외 — 환율 미도입)
- **오늘 손익의 기준일 (2026-09-12 지시)**: 오늘 봉이 아직 없으면(주말·공휴일·장 시작 전·일봉 적재 지연) **마지막 거래일의 변동**을 보여주고 카드·표에 그 날짜를 표기한다(`9/11 −113,285원 · 종가 기준`). 규칙은 하나 — **기준은 지금 쓰는 가격 바로 직전 값**: 실시간 시세가 있으면 현재가 vs **오늘 이전** 마지막 종가(애프터마켓에 오늘 종가가 이미 적재돼도 하루 전체 변동), 없으면 마지막 종가 vs 그 직전 종가. 종목 단위로 두 봉을 보므로 한·미 마감 시각 차이도 자동으로 맞는다. 총자산 카드는 같은 기준일의 스냅샷과 그 직전 스냅샷을 비교한다(보유 종목이 매매일지에만 있어도 기준일을 잡는다). 응답 필드: `change_asof`·`kr_stock.day_change_asof`·`portfolios[].day_change_asof`·`journals[].day_change_asof`(모두 null = 오늘). 종전에는 현재가·기준가가 모두 "오늘 이전 마지막 종가"라 새 봉이 없는 날 항상 0 이었다.
- 자산 추이 라인(1M/3M/6M/1Y/전체) — **총자산 + 포트별 다선**(KRW 포트, 2026-09-02) + **매매일지 합계 파선**(2026-09-10), 일간 손익 캘린더 히트맵
  - 범례 클릭으로 한 계열을 **강조**(이름·마지막 값 표기, 나머지는 흐리게)하고, 커서를 올리면 그 날짜의 계열별 금액을 함께 읽는다 (2026-09-10 지시)
  - 매매일지는 **일지 단위 스냅샷이 없어** 사용자 합계(`asset_snapshots.journal`) 한 줄로만 그린다. 집계 이전(NULL) 날짜는 0 으로 찍지 않고 건너뛴다
- **RAVG 레짐·노출 게이지**(현재 레짐, E, 목표 배분 — [feature-strategy-engine.md §8](feature-strategy-engine.md) `signals/history` 연동)
- 포트 성과 비교(실전 vs 백테스트 기대), 시세 기준시각 상시 표기

### 제외 범위

- 알림·이벤트 피드(후순위), 기타 자산의 시세 자동 평가(수동 입력 값 사용)

## 3. 사용자 시나리오

로그인 → 총자산과 전일대비 확인 → 레짐 게이지에서 "중립 / E=0.58" 확인 → 손익 캘린더에서 이번 달 성과 훑기 → 실전 포트 카드에서 백테스트 기대 대비 확인.

## 4. 최종 합의안

초기 범위는 자명한 읽기 집계였으나, 2026-09-02 자산 구분·포트별 추이 확장은 데이터 모델 신설을 수반해 Multi-Agent 검토를 수행했다.

### 검토 요약 (감사용)

- 참여 Agent: [Backend/Quant](../personas/backend-engineer.md), [Database](../personas/database-engineer.md), [QA](../personas/qa.md) (병렬 서브에이전트 3기, 2026-09-02)
- 핵심 쟁점과 결론: 포트 스냅샷을 **정수 원천**으로 확정하고 사용자 스냅샷은 합산 유도(반올림·시점 불일치 제거). 신규 FK는 CASCADE(포트 삭제 사고 재발 방지), 적재는 ON CONFLICT 단일문 + kst_today 통일(배치 UTC 결함 동시 수정), 행에 currency 비정규화. 미국 자산은 $ 별도 표기(환율 미도입 — 사용자 결정).
- 남은 쟁점: 소급 거래 시 과거 스냅샷 불변으로 인한 전일대비·캘린더 표시 왜곡은 `deferred`(§12 예외 케이스로 명문화), 환율 도입은 §15
- 검토 로그: [discussion/review-dashboard-asset-breakdown-20260902.md](../discussion/review-dashboard-asset-breakdown-20260902.md)

## 5. 기능 요구사항

- 총자산 = 보유 종목 평가액(현재가) + 현금(입출금 원장) + 기타 자산(수동 등록). 암호화 필드는 앱 레벨 복호 집계([feature-portfolio.md §10](feature-portfolio.md)).
- 일별 자산 스냅샷을 배치로 적재(추이·캘린더의 원천 — 소급 계산 아님).
- **스냅샷 원천·유도 (2026-09-02, [ADR-008](../adr/008-portfolio-snapshots.md))**: 포트 단위 스냅샷(portfolio_snapshots)을 정수로 먼저 확정하고, 사용자 asset_snapshots = Σ(KR 포트 equity) + 기타 자산을 **같은 트랜잭션에서 유도**한다. 적재는 `ON CONFLICT (portfolio_id, snap_date) DO UPDATE` 단일문, 날짜는 배치·API 모두 `kst_today()`.
- **실시간 표시 (2026-09-10)**: 화면의 총자산·주식은 10초 폴링 캐시(`quotes.live_quotes`)로 다시 평가한 값(`live_at` 동반), 전일 대비도 같은 총액으로 계산해 표시와 어긋나지 않게 한다. **적재되는 스냅샷은 종가 기준 그대로** — `compute_user_snapshot` 은 건드리지 않는다. 10초 갱신은 `GET /dashboard/live`(방문 기록·적재 없음)로만 한다.
- **시세 일괄 조회**: 스냅샷·카드 집계의 최신 종가는 종목 집합 단위 1쿼리(`DISTINCT ON`)로 조회한다 — 로트당 개별 조회(N+1) 금지.
- **자산 내용 카드**: 한국 주식 = 실전매매 KR 포트 합산 {평가액, 보유원가, 평가손익 금액, 평가손익%(÷보유원가)}. 미국 주식 = US 포트 합산을 센트 그대로 **$ 표기**(환율 미도입 — KRW 총자산·도넛·추이 합산에서 제외 유지).
- **상단 카드 구성 (2026-09-10 지시)**: 총자산 히어로 카드는 값 아래 **오늘**(어제 총자산 대비, 입출금 차감)과 **누적**(최초 스냅샷 대비, 입출금 차감) 두 줄만 둔다 — 종전의 "실전매매·매매일지" 구성 줄은 뺐다(같은 정보가 자산 구성 카드와 계좌별 현황 표에 있다). 서버가 `since_inception_amount` 를 함께 준다(종전 % 만). 한국·미국 주식 카드는 누적(보유 원가 대비) 아래 오늘(전일 종가 평가액 대비)을 붙인다. **두 '누적'의 기준이 다르므로**(총자산=최초 스냅샷, 시장 카드=보유 원가) 카드 라벨 ⓘ 로 구분해 적는다.
- **누적 손익 · 오늘 손익 분리 (2026-09-10 지시)**: 계좌별 현황과 매매일지 자산 표에 두 값을 함께 둔다 — **누적**은 매수 이후 평가손익(분모 = 보유 원가), **오늘**은 현재가 − **전일 종가**(분모 = 전일 종가 평가액). 현재가는 10초 폴링 캐시가 있으면 그것, 없으면 종가(`price_source`). 전일 종가가 없는 종목(오늘 신규 매수·시세 미확보)은 오늘 손익에서 빼고 `day_missing` 으로 이름을 알린다 — 매입가와 비교하면 누적과 같아져 뜻이 흐려지기 때문. 셀 수 있는 보유가 없으면 0 이 아니라 값 없음(`null` → 화면 '—'). 매매일지 행은 총자산에 넣는 종목(실전매매와 겹쳐 제외한 것 제외)만 센다.
- **매매일지 자산 평가 (2026-09-07 지시 ①③)**: 총자산에 포함되는 매매일지 보유의 현재가는 **증권사 잔고 → DB 종가 → KIS 일봉 보충(신규 종목 자동 등록)** 순으로 구한다. 코드 미입력 행은 `instruments` 이름 정규화 매칭으로 코드를 연결하되 **동명이 둘 이상이면 연결하지 않는다**(오연결 방지). 조회 실패 코드는 10분간 재시도하지 않는다(열람마다 외부 호출 억제).
- **평가 커버리지 표기 의무**: 시세를 끝내 못 구한 종목은 `summary.unpriced`(종목·코드·원가)로 드러내고, 보유수익률의 분모는 `cost_priced`(시세 있는 종목의 원가)임을 화면에 명시한다. **전체 원가와 부분 평가액을 나란히 표기해 수익률과 어긋나 보이게 하지 않는다** — 조용한 제외 금지.

- **거래 등록·삭제 시 당일 스냅샷 즉시 재계산** — 열람 시점에 적재된 당일 스냅샷이 삭제된 거래를 반영하지 못하는 유령값 방지(검토 Q1). 재계산 **직전에 `session.flush()`** — 세션이 `autoflush=False` 라 새 거래 행·재생 로트가 DB 에 없는 상태로 계산하면 "로트는 매도 후, 현금은 매도 전" 반쪽 스냅샷이 저장된다(2026-09-08 M-신한-ETF 매도 대금 3,420,000원 누락 → 다음 날 전일 대비 부풀림, NOTES). 등록·삭제·예수금 보정 세 경로 모두 적용, `tests/test_snapshot_consistency.py`.
- **과거 날짜 스냅샷 보정 도구 (2026-09-09)**: `python -m app.services.snapshot_repair --date YYYY-MM-DD [--user id|email] [--apply]` — 그 날짜에 체결된 거래까지의 FIFO 로트·현금(`signals._state_before`)을 그 날짜 이하 마지막 종가로 평가해 국내 포트 스냅샷과 사용자 총액을 다시 쓴다(journal·other 는 저장값 유지). 기본 dry-run.
- 기타 자산: 이름·분류(채권/펀드/금/코인/부동산 등)·평가액 수동 등록·수정.
- 벤토 그리드, 히어로 타일 화면당 2개 이하([REQUIREMENTS §7](../SOURCES/REQUIREMENTS.md)).

## 7. 데이터 설계

- `asset_snapshots(user_id, date, total🔒, stock🔒, cash🔒, other🔒)` — 일별 배치 적재, 🔒 암호화. **포트 스냅샷 합산의 유도값**([ADR-008](../adr/008-portfolio-snapshots.md)).
- `portfolio_snapshots(id, portfolio_id FK CASCADE, snap_date, equity🔒, stock_value🔒, cash🔒, currency, UNIQUE(portfolio_id, snap_date))` — 포트 단위 일별 스냅샷, currency(KRW|USD)는 적재 시점 비정규화(값 단위를 행 안에 보존). 일반 테이블(하이퍼테이블 불채택 — ADR-008 논증).
- `manual_assets(id, user_id, name, category, value🔒, updated_at)`.

## 8. API 설계

- `GET /portfolio/summary`(히어로·도넛·테이블), `GET /portfolio/trend?range=`, `GET /portfolio/calendar?month=`, `POST/PATCH/DELETE /manual-assets`.
- `/dashboard` 확장(2026-09-02): `kr_stock {value, cost, pnl, pnl_pct}` + `us_stock {value_cents, cost_cents, pnl_cents, pnl_pct}` — pnl_pct 분모(보유원가) ≤ 0 이면 null.
- `/portfolio/trend` 확장: 기존 `items` **비파괴 유지** + `series: [{portfolio_id, name, market, currency, points[{date, equity}]}]` 추가. 웹 차트는 `currency='KRW'` 시리즈만 그린다(US는 카드로만 — 환율 도입 시 재검토). ALL 구간의 series 는 주 단위 샘플(주 마지막 스냅샷).

## 12. 테스트 시나리오

### 자동 테스트

- 총자산 = 구성 요소 합 일치(암호화 복호 집계), 전일대비 계산, 스냅샷 결측일 처리(휴장일), 기타 자산 CRUD 소유자 격리(타인 접근 403).
- **합산 불변식(2026-09-02)**: 임의 (user, date)에서 `Σ(portfolio_snapshots.equity WHERE currency='KRW') + other == asset_snapshots.total`.
- **KR/US 혼재**: KR 포트(원) + US 포트(센트) 사용자 — kr_stock 에 센트 미혼입, us_stock 에 원 미혼입, trend `items`·total 은 KR 한정 유지, series 에 US 는 currency='USD' 로 반환.
- **중복 적재 유일성**: 같은 날 /dashboard 2회 열람 → (portfolio_id, snap_date) 행 수 1 (ON CONFLICT 갱신).
- **거래 삭제 후 정합**: 입금 → /dashboard(적재) → 입금 삭제 → trend 오늘 포인트 == summary total_equity.
- **포트 삭제**: 스냅샷 보유 포트 DELETE /portfolios/{id} → 200 (FK CASCADE).
- **매매일지 총 자본금 (2026-09-07 지시)**: 카드는 **계좌 연동 여부와 무관하게 항상 표시**하고 기준만 바뀐다 — 연동 O = **계좌 기준**(잔고 주식 평가액 + 예수금, 잔고만으로 구성해 일지 평가액과 섞지 않음), 연동 X = **일지 기준**(등록 보유 수량 × 현재가, 예수금 없음). 커버리지(계좌 보유 = 일지 보유·수량 일치)는 카드 표시 여부가 아니라 **수익률을 붙일 수 있는 범위인지**만 판정한다 — 계좌 총액에는 일지 밖 종목이 섞일 수 있어 불일치 시 수익률을 표시하지 않고 `account_mismatch`(종목·일지 수량·잔고 수량)로 사유를 보여준다. 대시보드 총자산에는 종전대로 주식 평가액만 반영.
- **매매일지 수익률 차트 코드 해석 (2026-09-07)**: 코드 미입력 종목도 이름 매칭으로 라인이 그려지고(`symbols[*].code` 채워짐) "시세를 붙일 수 없는" 안내가 뜨지 않는다 — 평가(도넛·카드)와 차트가 같은 규칙을 쓴다.
- **총 자본금 기준 전환 (2026-09-07)**: 미연동 일지 → `capital_basis == "journal"`, `capital_total == 등록 수량 × 현재가`, `capital_deposit is None`, 수익률 성립. 연동 일지 → `capital_basis == "account"`, 총액 = 잔고 주식 + 예수금이고 **커버리지 불일치여도 카드가 사라지지 않으며** 수익률만 `None`, `account_mismatch` 에 사유.
- **매매일지 평가 커버리지 (2026-09-07)**: 4종목(DB 적재·KIS 보충 대상·코드 없는 이름 매칭·불명) 일지에서 `priced_count == 3`, `cost_priced` 가 분모, `unpriced == [불명]`. 시세를 못 구한 종목이 분모에서 조용히 빠지지 않는다.
