# 주문표 → 증권사 예약주문 접수 (2026-09-05 결정·구현)

> 지시(2026-09-05): ① 장 마감 후 주문표에서 버튼으로 예약주문 접수, ② API 로 정상 접수가 확인되면 주문표에 등록완료 표시,
> ③ 15:30 장 마감 후 체결을 조회해 거래 기록·통계를 갱신, ④ KODEX 200 1주로 실계좌 테스트.
> 이 문서는 "조회 전용" 원칙(docs/market-research/10-broker-apis.md §4)을 **사용자 클릭 기반 예약주문**으로 바꾼 결정과 구현을 기록한다.

## 1. 원칙 변경
| 이전 | 이후 |
|---|---|
| 주문 TR 미사용, 사용자가 HTS 에서 직접 발주 | **예약주문 TR 만** 사용. 사용자가 주문표에서 버튼을 누르고 확인창을 거친 뒤에만 접수 |
| — | 정규 장중 주문(order-cash)·정정 TR 은 도입하지 않음. 자동(무인) 발주 없음 |
| 대조 경고만 | 유지 — 체결 가져오기·대조 경고·원장 자동 수정 금지는 그대로 |

근거: 주문표는 종가 확정 후 다음 거래일 실행분이라 KIS 예약주문 창(15:40 ~ 다음 영업일 07:30)과 정확히 맞고,
"사람이 최종 확인"이라는 방어선을 버튼 클릭 + 확인창으로 유지할 수 있다.

## 2. KIS TR (공식 예제 `koreainvestment/open-trading-api` 기준)
| 용도 | TR | 경로 | 비고 |
|---|---|---|---|
| 예약주문 접수 | `CTSC0008U` | `/uapi/domestic-stock/v1/trading/order-resv` | 지정가 00 / 시장가 01, 잔고구분 10(현금), 기간예약 최대 30일 |
| 예약주문 취소 | `CTSC0009U` | `/uapi/domestic-stock/v1/trading/order-resv-rvsecncl` | 정정(CTSC0013U)은 미도입 — 취소 후 재접수 |
| 예약주문 조회 | `CTSC0004R` | `/uapi/domestic-stock/v1/trading/order-resv-ccnl` | `rsvn_ord_seq`·`odno`(실주문번호)·`tot_ccld_qty`·`cncl_ord_dt`·`prcs_rslt` |

접수 창: 15:40 ~ 다음 영업일 07:30 (서버 초기화 23:40~00:10 제외). 휴장일은 종일 창 안. 모의투자에는 예약주문 TR 이 없다.

## 3. 구현
- **모델/0019** `broker_orders`: 주문표 한 줄 = 한 행 (`plan_date`, `line_key = kind:instrument:side:otype:price`, 종목코드, 예약순번, 실주문번호, 체결수량, 상태, KIS 메시지, 응답 원문). 활성(reserved) 상태의 같은 줄은 부분 유니크 인덱스로 중복 접수 차단.
- **API** (`app/broker.py`)
  - `GET /portfolio/{pid}/orders?date&refresh` — 접수 창 상태 + 기록. `refresh=1` 이면 KIS 조회로 체결/취소/미체결 확정.
  - `POST /portfolio/{pid}/orders/reserve {date, lines[]}` — 안전장치 순서: 연결 계좌(실전)만 → 접수 창 안 → 지난 실행일 거절 → **서버에 저장된 그날의 주문표 스냅샷과 줄이 정확히 일치**(불일치는 `mismatch` 로 거절, KIS 호출 없음) → 활성 예약 있으면 `duplicate` → 줄 단위 접수, 실패는 `failed` 로 기록하고 계속.
  - `POST /portfolio/{pid}/orders/{oid}/cancel` — 예약 취소.
  - `run_post_close_sync(session)` — 워커 15:45(17:10 재시도, 멱등): 연결 계좌마다 2일치 체결 가져오기(원장 재생 → 보유·수익률·통계 갱신), 예약주문 상태 확정, 연결된 매매일지 체결 가져오기. 일봉 수집(16:05) 전에 돌아 다음 주문표에 당일 체결이 반영된다(B안).
- **클라이언트** (`services/kis_client.py`): `reserve_order` / `cancel_reserved_order` / `list_reserved_orders`. 주문 POST 는 **재시도하지 않는다**(중복 접수 방지).
- **화면** (실전매매 주문표): "증권사에 예약주문 접수 (n건)" 버튼 → 확인창(계좌·실행일·줄 목록·지정가 합계) → 접수. 표의 "예약" 열에 ✓ 등록완료 #순번(취소 버튼) / ✓ 체결 n주 / ◐ 일부 체결 / ○ 미체결 / ✗ 접수 실패(사유). 창이 닫혀 있으면 버튼 비활성 + 사유 표시. "증권사 상태 새로고침"으로 즉시 확정 가능.

## 4. 위험과 방어선
| 위험 | 방어 |
|---|---|
| 잘못된 주문표로 접수 | 서버 스냅샷과 줄 일치 검증(수량·가격·종류), 확인창에 전 줄·합계 표시 |
| 중복 접수 | 활성 예약 유니크(DB) + 요청 내 중복 건너뜀, 주문 POST 무재시도 |
| 서버 장애 | 접수는 사용자 클릭 시점의 동기 호출 — 서버가 죽으면 아무 주문도 나가지 않음(안전 실패). 주문표는 그대로 남아 HTS 수동 발주 가능 |
| 부분 실패 | 줄 단위 상태 기록, 실패 줄만 재접수 가능 |
| 실주문과 원장 불일치 | 15:45 자동 체결 가져오기 + 기존 대조 경고. 원장 자동 수정은 하지 않음 |
| 계좌 오류(연금계좌 API 주문 미지원 가능성) | KIS 메시지를 한국어로 안내(`humanize_kis_error`), 계좌별 앱키 힌트 |

## 6. 실계좌 테스트 기록 (2026-09-05 토 19:00, 연금계좌 1004…-22)
KODEX 200(069500) 1주 지정가 매수 105,720원(9/4 종가)으로 접수 → 취소 → 재접수 순서로 실행했다.

| 단계 | KIS 응답 |
|---|---|
| ① 접수 | `rsvn_ord_seq=84616`, "예약주문이 접수되었습니다." |
| ② 취소 (CTSC0009U, RSVN_ORD_ORGNO 빈값) | "처리 완료 되었습니다", `NRML_PRCS_YN=Y` |
| ③ 재접수 (유지) | `rsvn_ord_seq=84617` |
| 조회 (CTSC0004R) | 84617 · 주문일자 **20260907**(다음 영업일) · 접수일 20260905 · 1주 @105,720 · 체결 0 · 결과 "미처리" |

확인된 사실:
- **연금저축계좌(22)도 API 예약주문이 접수된다** — §1 의 "연금계좌 미지원 가능성"은 기우였다.
- 휴장일(토요일) 접수가 가능하며 주문일자는 다음 영업일로 잡힌다.
- 조회 API 의 일자 범위는 **주문일자(실행일) 기준**이다. 접수일만으로 조회하면 0건 — `sync_orders` 는 접수일~실행일을 덮도록 고쳤다.
- 취소된 예약(84616)은 `CNCL_YN=Y` 로도 조회에 나오지 않았다. 그래서 조회에서 사라진 행은 건드리지 않고(보수적), 실행일이 지나면 "미체결"로 확정한다.
- 조회 응답의 `ord_dvsn_cd` 는 지정가 주문이 `01` 로 왔다(접수 코드 00 과 다른 코드표). 상태 판정에는 쓰지 않는다.

84617 은 사용자 확인용으로 남겨 두었다 — 월요일(9/7) 장 시작 시 105,720원 지정가 매수 1주가 나간다. 취소는 HTS 또는 화면(연결 후) 에서.
