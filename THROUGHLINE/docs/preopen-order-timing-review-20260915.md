# 09:01 발주를 08:30~09:00 동시호가로 옮길 것인가 · 예상체결가로 폭락을 판단할 것인가 (2026-09-15)

> 지시: "1. 09:01 분에 주문 넣지 말고 08:30~09:00 사이에 주문을 넣는 방안을 검토하세요.
> 2. 09:00 시가에 폭락이 있을 경우에는 시작 전 거래에서 예상가를 기반으로 판단이 가능한지 검토하세요."

**결론: 1번 기각, 2번 조건부 기각(데이터 적재만 채택 권고).**

제안의 실효는 **갭 취소를 잃는 것 하나**로 수렴한다. 체결 건수는 같고, 체결 가격은 오히려 현행이 낫다.
그리고 2번은 1번을 채택할 때만 필요한 보완책인데, 정확도를 잴 **데이터가 존재하지 않는다**.

## 0. 두 방식이 실제로 다른 지점

| | 현행 A (ADR-009) | 제안 B |
|---|---|---|
| 발주 시각 | 09:01 | 08:30~09:00 동시호가 |
| 09:00 단일가 참여 | **불참** | 참여 — 단일가 ≤ 지정가면 **단일가에** 체결 |
| 갭 취소 | **가능** — 확정 시가로 `시가 ≤ 종가−1.5×ATR` 판정 | **불가능** — 시가를 보기 전에 넣는다 |

이 구조는 새 것이 아니다. **B 가 원래 방식이었다.** [ADR-008](../adr/008-controlled-auto-execution.md) §배경:

> 실전은 전날 예약주문을 넣어 09:00 동시호가에 그리드 지정가가 들어가므로 갭이 나면 시가에 그대로 체결됐다.
> 시가는 09:00 에야 확정되어 "미리 취소"가 불가능하고 (…) **실전과 백테스트가 어긋나는 유일한 지점이었다.**

[ADR-009](../adr/009-unattended-single-execution.md) 가 이를 09:01 단일 실행으로 바꿔 그 어긋남을 없앴다.

## 1. 측정 — 분봉 251일 (`scripts/preopen_timing_study.py`)

KODEX 200 1분봉 2025-08-28 ~ 2026-09-10(251일, 일 379봉)에 실제 플래너 계획(그리드 매수 353줄, 125일)을 겹쳤다.
`09:00 봉의 시가 = 단일가`, `09:01 봉의 시가 = 실행기가 발주하는 순간의 값`.

### ① 체결 건수 — 비갭일에는 **완전히 같다**

```
전체 353줄 · 현행 A 59줄 · 제안 B 72줄 · B만 13줄 · A만 0줄
  └ B만 13줄은 전부 갭일. 비갭일에서 B 가 더 얻는 체결은 0줄.
```

지정가에 닿는 날은 09:00 단일가에만 닿고 마는 일이 없었다 — **하루 중 다시 닿는다.** 09:01 로 늦춰서
놓치는 체결은 비갭일에 **하나도 없다.**

### ② 체결 가격 — 현행이 **더 싸다**

둘 다 체결되지만 단일가가 지정가 아래로 열린 21줄에서:

| | 값 |
|---|---|
| A(09:01) − B(단일가) | **−0.183%** (평균) · −0.177% (중앙) |
| A 가 더 비쌌던 날 | **6 / 21** |

약하게 열린 날은 첫 1분에 더 내리는 쪽이 잦았다. "먼저 사는 것"이 유리하다는 직관과 **반대**다.

### ③ 차이는 전부 갭일에서만 — 그리고 그것이 곧 갭 취소

표본(1년)에서는 갭일 매수가 오히려 잘됐다(13건, 5일 뒤 평균 +5.50%, 이익 11/13). 그러나 이 구간은
1년 +118% 의 강세장이라 **"급락일에 사면 이득"이 표본 편향으로 나오기 쉬운 구간**이다. 그래서 장기로 다시 쟀다.

### ④ 부수 발견 — 백테스트는 A 와 B 의 좋은 쪽만 합친 혼합이다

`_fill_limit_buy` 는 `open ≤ 지정가면 **open 에** 체결`한다. 즉 **주문이 09:00 단일가부터 살아 있다고 가정**(=B)
하면서, 갭 취소는 **확정 시가**로 판정(=A)한다. 물리적으로 동시에 성립할 수 없는 조합이다.

다만 ①②가 보여주듯 이 혼합의 실제 오차는 현행에 **불리하지 않다** — 체결 건수는 같고, 가격은 현행이
0.18% 싸다. 백테스트가 현행을 과대평가하는 것이 아니라 **과소평가**하고 있다. 수정 필요는 없고, 기록해 둔다.

## 2. 측정 — 갭 필터 단독 절제, 89창 (`scripts/gap_filter_ablation.py`)

2026-08-28 절제 리포트의 ⑤ 는 `f5_gap_filter` 를 통째로 꺼 **갭 필터 + 잔여예산**을 함께 껐다(+11.7%p).
여기서는 `gap_atr_mult` 만 거대하게 만들어 **갭 취소만** 무력화하고 잔여예산은 유지했다.
일봉 2,374일(2017-01-02 ~ 2026-09-10), 시작일 21일 간격 89창 × 각 246거래일 짝 비교.

| 제안(갭 취소 없음) − 현행 | 값 |
|---|---|
| 수익률 평균 | **+0.112%p** |
| 수익률 중앙 | **+0.000%p** |
| 이김 : 짐 : 동일 | **17 : 18 : 54** |
| 수익률 최악 / 최고 | **−2.821%p** / +3.467%p |
| MDD 평균 | −0.001%p (불변) |
| **MDD 최악** | **−3.545%p** |

가장 나빴던 창: 2018-01-25(−2.82%p, MDD −3.55%p) · 2018-02-27(−2.66%p) · 2020-01-16(−1.45%p) · 2020-02-18(−1.42%p).

**89창 중 54창에서 결과가 완전히 동일하다** — 갭 취소는 연 4~5회만 발동한다. 평균 +0.11%p 는
[노이즈 밴드](validation-methodology-20260913.md) 안이고 승패는 17:18 로 동전 던지기다.
값은 평균이 아니라 **꼬리**에 있다: 나빴던 창이 전부 2018-02 변동성 급등과 2020-03 코로나에 몰려 있다.

전형적인 보험의 손익 구조다 — 평상시 비용 ≈ 0, 위기에 지급. 정본 §12 의 목표("최대 수익이 아니라
위험 대비 효율")에 정확히 부합하는 장치다.

## 3. 1번 판정 — 기각

제안이 현행보다 나은 항목이 **하나도 없다.**

| 기준 | 판정 |
|---|---|
| 체결 건수 | 동일 (비갭일 59 = 59) |
| 체결 가격 | **현행 우세** (−0.183%) |
| 갭 방어 | **현행 우세** (최악 창 MDD +3.5%p) |
| API 유량 | 현행 우세 — 08:30~09:00 은 예상시가 폴링(매 분)과 겹친다. 09:01 쏠림은 06:30 토큰·08:45 잔고 선조회로 이미 해소 |
| 백테스트 정합 | 현행 우세 — ADR-008 이 없앤 "실전과 백테스트가 어긋나는 유일한 지점"을 되살리게 된다 |

**09:00 을 향해 더 당기는 것도 이득이 없다.** 09:00~09:01 구간이 더해 주는 체결은 비갭일 0줄이고,
가격은 09:01 쪽이 쌌다. 현행 09:01 은 이 세 축에서 최적에 해당한다.

## 4. 2번 판정 — 예상체결가를 판단 근거로 승격하지 않는다

### 이미 만들었다가 뺐다

`app/preopen.py` 의 08:57 사전 갭 취소는 [ADR-008 통제 조건 13](../adr/008-controlled-auto-execution.md)으로
2026-09-06 에 채택돼 실제로 동작했고, ADR-009 가 **"09:01 실제 시가로 판정하므로 불필요"** 로 삭제했다.
지금 남은 것은 `app/preopen_watch.py` 의 **표시 전용** 관찰이며, `expected_open_view()` 는
이미 `gap_hit`(예상가 ≤ 갭 기준)을 계산해 주문표에 "예상 시가 … 갭 기준 위/이하"로 보여 준다.
**판단 재료는 이미 화면에 있다. 없는 것은 그것을 근거로 삼을 자격이다.**

### 정확도를 잴 데이터가 없다

- 예상체결가는 동시호가 호가 잔량으로 계산한 **근사값**이다 (ADR-008 기각 사유에 명시).
- 관찰 표본은 Redis `preopen:expected:{code}:{date}` 에 **TTL 12시간**으로만 있고 **DB 에 적재되지 않는다**
  (`preopen_watch.py` 밖에 기록 경로 없음 — 확인함). 오늘 것도 이미 만료돼 남아 있지 않다.
- KIS 는 **과거 예상체결가를 제공하지 않는다.** 분봉도 09:00 부터라 장 시작 전 구간이 없다.

→ "예상가로 판단해도 되는가"는 지금 **백테스트로 답할 수 없다.** 답할 수 없는 것을 근거로 실주문 규칙을
바꾸지 않는다.

### 그리고 애초에 필요하지 않다

예상가 판정이 필요해지는 상황은 **1번을 채택했을 때만** 생긴다. 현행은 **확정 시가**로 판정하므로
근사값이 필요 없다. 사용자가 걱정한 "09:00 폭락"은 현행이 이미, 그것도 더 정확한 값으로 처리한다 —
`시가 ≤ 종가 − 1.5×ATR` 이면 그리드·초기 진입 매수를 전부 생략하고(`skipped_gap`) 주문표·로그·알림에 남긴다.
익절 매도와 레버리지 청산은 대상이 아니다(폭락에 팔 수 있어야 하므로).

### 채택 권고 — 표본 적재 하나

지금 할 수 있는 유일하게 의미 있는 조치:

> **`preopen_watch` 표본을 DB 에 남긴다** (거래일 × 종목 × 분 → 예상가, 그리고 확정 시가).

싸고 되돌릴 수 있으며, 몇 달 쌓이면 "예상체결가 ↔ 실제 시가" 오차 분포를 **처음으로** 잴 수 있다.
그때 비로소 이 질문에 답할 자격이 생긴다 — 특히 급락일(지금 연 4~5회)에 예상가가 얼마나 맞는지가 핵심이다.
**다만 그 데이터가 쌓여도 1번의 판정은 바뀌지 않는다** — §3 의 다섯 기준 중 예상가가 회복해 줄 수 있는 것은
갭 방어 하나뿐이고, 나머지는 여전히 현행이 같거나 낫다.

> **이행됨 (2026-09-15 지시 "둘다 진행하세요")** — `preopen_samples` 표(마이그레이션 0029)에 매 분 표본을 남긴다
> (`preopen_watch.persist_sample`). Redis 는 표시용 그대로. **판정에는 여전히 쓰지 않는다.**
> 재검토 시점: 급락일 표본이 10건을 넘길 때(연 4~5회이므로 2년 남짓).

## 5. 한계

- 분봉 측정은 **251일 1구간·KODEX 200 단일 종목**이다. 갭일 5일(13줄)은 작은 표본이며, 이 구간이 강세장이라
  갭일 매수의 사후 성과(+5.5%)는 **유리하게 나올 소지가 있다**. 그래서 판정 근거를 여기 두지 않고 §2 의 89창에 두었다.
- 89창은 겹치는 창이라 독립 표본이 아니다(validation-methodology). 분포를 보는 도구로만 썼다.
- 동시호가의 **부분체결·호가 잔량**은 범위 밖이다. 단일가 체결을 "단일가 ≤ 지정가면 전량"으로 가정했다 —
  B 에 유리한 가정이며, 그래도 B 가 이기지 못했다.
- 이 검토는 국내(KR) 경로다. 미국(TF·LTM)은 무인 발주 대상이 아니다.
