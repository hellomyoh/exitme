# 브랜드 마크 개정 — A안 "열린 문" 채택 (2026-09-10)

사용자 지시로 마크 개정안 세 안(A 열린 문 / B 문턱을 넘다 / C 두 갈래) 가운데 **A안**을 적용했다.
개정안 원문은 대화 산출물(Artifact)로 남아 있고, 이 문서는 저장소에 반영된 결과만 기록한다.

## 1. 왜 바꿨나

종전 마크는 `#17181c` 짙은 사각형 안의 흰 마름모였다. 형태에 뜻이 없어 이름과 따로 놀고,
화면에서 가장 무거운 요소가 로고가 됐다. A안은 **문틀 세 면 + 그 사이로 빠져나가는 상승 화살**이다.
`Exit` 이라는 이름을 그대로 그린 형태라 설명이 필요 없고, 화살의 45° 축이 상승·활기를 맡는다.

B(막대 3단)는 그리드 매수와 겹쳐 뜻이 좋았으나 이름과 이어지지 않고, C(두 갈래 헷지)는
이야기가 가장 정확하지만 16px 에서 두 선이 붙어 읽히지 않아 각각 대안으로 남긴다.

## 2. 형태 — 32 그리드, 획 3.1

```
문틀   M22 5H10a5 5 0 0 0-5 5v12a5 5 0 0 0 5 5h12   stroke=currentColor
화살대 M14.8 20.2 26.4 8.6                          stroke=var(--color-brand)
화살촉 M19.6 7.4h7.6V15                             stroke=var(--color-brand)
```

문틀은 `currentColor` 라 놓인 자리의 글자색을 따르고 화살만 브랜드색으로 고정한다.
밝은 바탕·어두운 바탕에 같은 파일 하나로 대응하려는 것이다.

## 3. 색 — 브랜드색 청록 `#0d9488`

`--color-brand` 를 새로 뒀다. 이 앱에서 **빨강=상승, 파랑=하락, 초록=정상, 주황=강조**로 색의 뜻이
이미 차 있어, 청록만이 어떤 수치도 뜻하지 않는 빈 자리다. 로고 전용으로만 쓴다(차트·수치에 쓰지 않는다).

## 4. 반영한 곳

| 파일 | 자리 |
| --- | --- |
| `apps/web/components/brand.tsx` | `BrandMark`(마크)·`BrandWord`(로고타입) — 네 곳이 같은 것을 쓴다 |
| `apps/web/components/nav.tsx` | 사이드바 로고 32px, 모바일 상단 바 28px |
| `apps/web/components/shell.tsx` | 세션 확인 중 로딩 표시 20px |
| `apps/web/app/login/page.tsx` | 로그인 카드 상단 32px |
| `apps/web/app/icon.svg` | 파비콘 — CSS 변수를 못 읽어 색을 박고, 16px 을 버티게 획을 **3.6** 으로 올렸다 |
| `apps/web/app/apple-icon.png` | 180×180 흰 바탕 (iOS 는 투명을 검게 깐다) |
| `apps/web/app/globals.css` | `--color-brand: #0d9488` |

파비콘 획은 3.1·3.6·4.0·4.6 을 16px 실제 래스터로 찍어 비교했다. 4.0 부터 화살촉이 뭉쳐 **3.6** 으로 정했다.
Next.js App Router 가 `app/icon.svg`·`app/apple-icon.png` 를 자동으로 `<link>` 로 걸어 `layout.tsx` 는 건드리지 않았다.

**마크 경로는 두 곳에 있다** — `brand.tsx` 와 `icon.svg`. 형태를 고치면 둘 다 고쳐야 한다.

## 5. 함께 제안됐으나 하지 않은 것

- **accent 토큰 정리**: `--color-accent` 는 `#c2410c`(진한 벽돌)인데 `--color-accent-dim` 은
  `#f97316`(밝은 주황) 12% 다. 둘을 `#ea580c` 계열로 모으자는 제안 — 강조색은 화면 전반에 걸려 있어
  따로 판단할 일이라 남겨 둔다.
- **부제 문구**: `AUTO TRADING` 은 어느 자동매매 앱에도 붙는다. "규칙이 지키는 매매" 가 이 앱을 더
  정확히 말한다는 제안 — 문구 변경은 지시받지 않아 그대로 뒀다.
