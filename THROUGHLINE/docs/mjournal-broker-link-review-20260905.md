# 매매일지 ↔ 증권사 계좌 연동 검토 (2026-09-05)

> 지시: "매매일지에도 계좌를 연결해서 매매 기록을 가져와서 보여 줄 수 있는지 분석하고 검토하세요."
> 결론 먼저: **가능하고, 실전매매(포트폴리오)에 이미 붙인 조회 전용 연동을 그대로 재사용하면 작업량이 작다.**
> 다만 종목 이름 매칭·가져오기 이전 보유분·중복 방지 세 가지를 설계에 넣어야 한다. 이 문서는 분석과 권고안이며, 구현은 별도 지시로 진행한다.

## 2. 설계 쟁점과 권고

### 2-1. 일지와 계좌의 대응 관계 — "일지 1 : 증권사 계좌 1"
- KIS 계좌는 `종합계좌 8자리 + 상품코드 2자리`(예: 연금저축 = 22, 위탁 = 01)로 식별된다. 사용자의 일지 이름("연금저축")도 실제로 계좌 단위다.
- 권고: `manual_journals.broker_credential_id` FK(ON DELETE SET NULL) 하나를 추가하고, 포트와 같은 `GET/PUT /mjournals/{jid}/broker` 로 연결·해제한다. 한 계좌를 여러 일지에 연결하는 것은 허용(조회 전용이라 부작용 없음)하되, 같은 체결이 두 일지에 들어갈 수 있음을 화면에 안내한다.

### 2-2. 종목 매칭 — 가장 손이 가는 부분
- 일지 종목은 사용자가 친 자유 텍스트("kodex 200")이고, KIS 는 코드("069500")와 정식 종목명("KODEX 200")을 준다.
- 권고(3단계):
  1. 일지에 이미 있는 종목명과 **대소문자·공백 무시** 비교로 일치하면 그 종목명으로 귀속한다 (`kodex 200` ≡ `KODEX 200`).
  2. 일치가 없으면 KIS 종목명을 새 종목으로 추가한다 (일지가 다종목을 지원하므로 자연스럽다).
  3. 항목에 `code`(6자리)를 함께 저장해 이후 가져오기는 코드로 정확히 매칭한다. 종목명 변경(리브랜딩)에도 안전하다.
- 미리보기(dry-run) 표에 "kodex 200 ← KODEX 200(069500)" 처럼 매칭 결과를 보여주고 사용자가 확인한 뒤 등록한다.

### 2-3. 가져오기 이전 보유분 — 매도 초과 오류
- 일지의 매도 등록은 "해당일 보유 초과"를 422 로 거절한다(종목별 FIFO). 계좌에 **가져오기 시작일 이전에 산 주식**이 있으면 첫 매도가 전부 거절된다.
- 권고: 가져오기 경로에서는 거절 대신 **경고 행으로 등록**한다. `_compute` 는 이미 `error: "보유(n주)보다 많은 매도"` 행을 만들어 표에 ⚠ 로 보여준다. 여기에 "기초 보유 등록" 버튼(일자·수량·평단을 한 번 넣는 매수 행)을 안내해 사용자가 채우도록 한다. 실전매매 시작 패널의 "현재 보유분 입력"과 같은 개념이다.
- 잔고 API(`inquire-balance`, `probe_balance` 가 이미 호출)로 현재 보유 수량·평단을 읽어 **기초 보유 제안값**을 자동으로 채울 수 있다. 다만 KIS 평단은 이동평균이라 FIFO 로트로는 근사다 — 실전매매 검토(manual-holdings-tp-review-20260903.md)와 같은 한계를 안내문에 적는다.

### 2-4. 비용(수수료·세금)
- 체결 조회 응답에는 수수료·세금 항목이 없다. 일지는 요율(수수료 0.015%, 제세금 0.23%)로 계산하므로 **가져온 행도 같은 요율을 적용**하면 일관된다. 실제 정산 금액과의 오차는 원 단위 수준이며 화면 문구("요율 기준 추정")로 명시한다.

### 2-5. 조회 범위와 유량
- `fetch_executions` 는 3개월 이내/이전 TR 을 자동 선택하므로 과거분도 가져올 수 있다. 첫 연결 시 기본 30일, 최대 1년(옵션)으로 제한해 호출 수를 억제한다.
- 토큰은 자격 해시 단위로 Redis 공유(#83), 분당 1회 발급 제한은 대화형 경로에서 즉시 안내(#81). 일지 가져오기도 같은 경로를 타면 추가 위험이 없다.

### 2-6. 원칙 유지 — 조회 전용, 자동 수정 금지
- 주문 TR 은 쓰지 않는다. 가져온 행은 `broker_ref` 로 표시하고 사용자가 삭제할 수 있다. 수동 입력 행을 자동으로 고치거나 합치지 않는다 — 실전매매 대조와 같은 "경고만" 원칙.
- 수동 행과 가져온 행이 같은 체결일 때(사용자가 먼저 손으로 적어둔 경우) 자동 병합은 하지 않고, 미리보기에 "같은 날 같은 종목·수량·단가의 수동 기록 있음" 경고를 붙여 사용자가 하나를 지우게 한다.

### 3-1. 후속 구현 — 잔고 기준 기초 보유 등록 (2026-09-05 저녁)
실사례: "한투-삼성" 일지에서 체결 가져오기에 계좌의 삼성전자 11주가 안 보임 — 체결 가져오기는 **기간 안의 체결**만
가져오므로 그 전에 산 보유분은 나오지 않는다(2-3 에서 예고한 한계). 권고대로 잔고 API 로 보완했다.
- `GET /mjournals/{jid}/broker-holdings` — 연결 계좌 잔고(`inquire-balance` output1: 종목·수량·평단·현재가)를 일지 보유와
  종목별로 대조해 부족분(`diff`)을 등록 제안 수량으로 준다. 종목 매칭은 체결 가져오기와 같은 3단계.
- `POST /mjournals/{jid}/import-holdings` — 선택한 종목을 등록일 기준 '기초 보유' 매수 1건으로 넣는다(계좌 평단 사용,
  `broker_ref=bal:코드:일자` 로 같은 날 중복 방지, 청산 일지는 409).
- 화면: 증권사 연동 카드 아래 "현재 잔고로 기초 보유 등록" — 잔고 조회 → 표(계좌 보유/일지 보유/등록 수량/평단/현재가) →
  부족분 기본 선택 → 선택 등록. 안내문에 "이동평균 평단·등록일 기준 근사, 실제 매수일이 필요하면 체결 기간을 늘려라"를 명시.

## 4. 하지 않기로 한 것
- **잔고 기반 자동 동기화**(체결 없이 현재 보유만 맞추기): 일지의 목적(매매 기록·실현손익)과 어긋나고, 이동평균 평단으로 FIFO 를 만들 수 없다.
- **일지 간 합산 뷰 복원**: 2026-09-05 지시로 일지 간 완전 분리를 택했다. 계좌별 합산이 필요하면 대시보드 쪽에서 별도 카드로 다룬다.

## 5. 함께 고친 것 (같은 날)
- 새 일지에 다른 일지의 종목·보유 비중·수익 라인이 보이던 문제: 화면 하단 "전체 현황"이 **전 일지 합산**이라 새 일지(기록 0건)에서도 다른 일지의 도넛·라인이 그려졌다. `/mjournals/overview` 를 제거하고 `/mjournals/{jid}` 응답에 종목별 누적 실현 시리즈를 넣어, 모든 숫자·그래프·종목 목록이 선택한 일지 하나의 것만 쓰도록 바꿨다. 계정 간 격리는 소유자 검사(404)로 이미 강제되며 회귀 테스트를 추가했다.


## 3-2. 보유 평단 대비 일별 수익률 라인 (2026-09-06 지시 · 구현)

- 배경: 현황 그래프가 매도 기록으로만 그려지는 누적 실현손익 라인이라, 보유만 하는 종목(예: 삼성전자 11주)은 수익 추이가 전혀 보이지 않았다.
- API `GET /mjournals/{jid}/return-series` — 종목별 보유 구간(`segments`, 보유 중인 날만)·현재 보유 여부·평단·현재 수익률, 일지 종합(`total` = 보유 평가액 합 ÷ 보유 원가 합 − 1), 안내(`notes`).
  - 평단 = 그날 시점 FIFO 잔여 로트 원가 ÷ 수량 (보유 카드의 평단과 같은 값). 추가 매수·부분 매도로 바뀐 날부터 반영.
  - 시세: DB 일봉 → 구간이 비거나 꼬리가 4일 넘게 오래되면 KIS 일봉(`fetch_daily`)으로 보충·적재(`Instrument` STOCK 생성 → 이후 16:05 일봉 배치가 이어 붙임). 키는 일지 연결 계좌 → .env 시세 키 순, 없으면 안내만.
  - 마지막 점: 연결 계좌 현재가가 있으면 오늘 값으로 덧붙임(`live`), 종합도 오늘은 현재가로 재합산.
  - 종목 코드가 없는 수동 종목은 시세를 붙일 수 없다 → 기록 입력에 "종목코드(선택)" 필드 추가(`EntryIn.code`).
- 화면: 현황 카드 우측에 탭 "보유 수익률 (%)" / "누적 실현손익 (원)". 보유 종목에 수익률이 있으면 % 탭이 기본. 구간마다 별도 라인(청산 뒤 재매수를 직선으로 잇지 않음), 0% 기준선, 보유 2종목 이상이면 종합 점선, 청산 종목은 토글로 점선 표시. 도넛 풍선에 평가 수익률·보유 기간 추가, 범례에 현재 수익률.
- 테스트: `test_journal_return_series_fifo_avg_and_segments`(평단 변화·청산 구간·종합 가중·키 없음 안내), `test_journal_return_series_fetches_missing_bars`(KIS 보충·적재·재호출 시 꼬리만).
- 주의: 액면분할 종목은 원주가 기준 일봉과 체결가가 어긋날 수 있다(분할 전 구간). 해외 종목(코드 6자리 아님)은 대상 외.


## 3-3. 계좌 평가금액 (주식 평가액 + 예수금) — 2026-09-06 지시

- 배경: 일지 카드가 손익만 보여 줘 "지금 이 계좌에 얼마 있나"에 답하지 못했다. 일지에는 현금 개념이 없어(입출금 기록 없음) 잔고의 출처는 연결 계좌뿐이다.
- 구현: `KisTradingClient.fetch_balance()` 가 보유(output1)와 함께 **예수금·총평가(output2)** 를 반환한다(`fetch_holdings` 는 이 결과의 보유만 돌려주는 얇은 래퍼). 잔고 캐시(120초)에 `__account__ = {deposit, rows}` 를 함께 담아 **추가 API 호출 없이** 현재가 조회 한 번으로 예수금까지 얻는다.
- **커버리지 판정**: 계좌 보유 종목이 모두 일지에 있고 수량이 일치하며, 일지에 계좌 밖 종목이 없을 때만 `account_covered=True` → `account_total = eval_total + deposit`. 아니면 `account_total=None` 으로 카드를 감춘다.
  - 이유: 일지 ≠ 계좌인데 예수금을 더하면 계좌 총액도 일지 총액도 아닌 값이 된다. 한 계좌를 여러 일지에 연결하는 것도 허용되므로(§3 링크 규칙) 중복 위험이 있다.
- **대시보드 총자산에는 예수금을 넣지 않는다** — 일지 화면 참고 값. `journal_assets` 의 `value` 는 종전대로 주식 평가액(또는 취득원가).
- 예수금은 D+2 정산 기준(`dnca_tot_amt`)이라 매도 직후 인출 가능액과 다를 수 있다 — 카드 풍선말에 명시.
- 테스트: `test_journal_account_total_only_when_journal_covers_account` — 커버 시 합계·대시보드 미포함, 계좌 밖 종목 섞임·수량 불일치 시 표시 안 함.
