# 보유 시작 vs 콜드 스타트 — 계산이 끝까지 구분되는가 (2026-09-13)

> 지시: "기존 보유량이 있을 때 시작한 실전매매와 보유 없이 초기 진입으로 시작한 실전매매가 **정확히 구분되어**
> 계산되는지 검토하라."

**결론: 구분된다.** 갈라지는 지점 6곳을 코드로 확인하고 end-to-end 테스트로 고정했다
(`test_cold_start_and_holdings_start_are_accounted_separately`). 다만 사용자가 오해할 수 있는 경계 하나를 §4 에 적는다.

## 1. 두 시작 경로 (화면 기준)

| | 현금만 시작 | 보유분 입력하고 시작 |
|---|---|---|
| 입금 기록 | `deposit = 현금` (memo "시작 입금") | **`deposit = 현금 + 보유 원가`** (memo "시작 입금 (현금+보유 원가)") |
| 매수 기록 | 없음 | 종목마다 `buy`(수량·평단) — 평단 미입력 시 최근 종가 |
| 기록 시각 | 최근 종가일 15:30 KST | 같음 |

입금에 **보유 원가를 더하는 것**이 핵심이다. 그래야 매수 기록이 현금을 깎아도 원장 현금이 정확히 `현금` 으로 남고,
수익률 분모(납입원금)에 보유분이 포함된다.

## 2. 갈라지는 지점 6곳 — 전부 확인

| # | 지점 | 콜드 스타트 | 보유 시작 | 근거 |
|---|---|---|---|---|
| 1 | **소량 진입(부트스트랩, ADR-010)** | 적용 (첫 10거래일) | **미적용** | `signals.py` — 시작일까지 등록된 매수가 있으면 `days_since_start = None` |
| 2 | 백테스트의 같은 판정 | `days_since_start` 계산 | **None** | `backtest.py:192` — `None if initial_lots` |
| 3 | **수익률 분모(납입원금)** | 현금 | **현금 + 보유 원가** | `portfolios.py:649` `principal = Σdeposit − Σwithdraw`, 백테스트 `base_capital = capital + Σ(qty×price)` — **같은 규약** |
| 4 | 원장 현금 | 현금 | **현금** (입금−매수) | 입금에 원가를 포함하므로 음수가 되지 않는다 |
| 5 | 보유 수량 | 0 | 입력 수량 | 주문표 `account.qty_200` |
| 6 | **로트 종류·익절** | 그리드 체결분이 태그를 갖는다 | **태그 없음** → 상승장 `core`(익절 없음) / 그 외 `grid` + 최근 종가×(1+Grid) | `lots.rebuild_lots` |

`평가손익%` 의 분모는 둘 다 `invested_cost`(보유 원가 합)로 같다 — 콜드 스타트는 처음 0 이고 체결이 쌓이며 늘어난다.

## 3. 검증 — end-to-end 테스트

화면 시작 패널의 두 경로를 그대로 재현해 한 테스트에서 비교한다(`tests/test_signals.py`):

```
현금만 시작   → boot 주문 있음 · boot{day,days} 표시 · qty_200 = 0   · cash = 5,000만 · principal = 5,000만 · invested_cost = 0
보유분 시작   → boot 주문 없음 · boot = None        · qty_200 = 100 · cash = 5,000만 · principal = 1억 1,000만 · invested_cost = 600만
```

특히 **보유 시작의 원장 현금이 5,000만 그대로**인 것과 **납입원금에 보유 원가가 들어간 것**을 함께 못박았다.
후자는 2026-09-02 에 발견된 결함(현금만 분모로 쓰면 보유 평가액이 통째로 수익 — +153% 사례)의 회귀 방지다.

## 4. 구분되지 **않는** 것 (의도된 설계)

- **레짐·E·그리드 가격**은 시장만의 함수다. 시작 방식과 무관하게 같다 — 두 포트가 같은 날 같은 가격의 그리드 주문을 받는다.
- **익절·축소 규칙**은 "지금 무엇을 얼마나 들고 있는가"만 본다. 어떻게 시작했는지는 보지 않는다.
- 이것이 옳다. 시작 방식은 **초기 조건**이지 전략의 상태 변수가 아니다.

## 5. 경계 하나 — 시작일에 직접 산 경우

`started_with_holdings` 는 **시작일(= max(포트 생성일, 첫 거래일))까지 등록된 매수**가 하나라도 있으면 참이다.
따라서 이런 경우가 콜드 스타트가 아니게 된다:

- 현금만으로 시작한 뒤, **같은 날** 사용자가 직접 산 체결을 등록 → 부트스트랩 꺼짐
- 과거 매수를 소급 등록(예: 지난달 산 것) → 시작일 이전이므로 역시 보유 시작

설계 의도대로다(ADR-010 은 "보유 0 으로 시작한 콜드 스타트 전용"). 다만 사용자 입장에서는 *"현금으로 시작했는데
초기 진입 주문이 안 나온다"* 로 보일 수 있다. **다음 날 등록한 체결은 영향이 없다** — 시작일보다 뒤이므로 부트스트랩이
계속된다.

필요하면 주문표에 사유를 한 줄 표시할 수 있다(예: "보유로 시작한 포트 — 초기 진입 대상 아님"). 지금은 표시가 없다.

## 6. 한계

- 이 감사는 **국내(KR) 경로**를 봤다. 미국(TF·LTM)은 부트스트랩 규칙 자체가 없어 구분 대상이 아니다.
- 백테스트→실전 전환(`from_backtest`)도 보유 시작으로 취급된다(입금 = 현금 + 로트 원가, 매수 기록 생성) — §2 와 같은 경로다.
- 태그 없는 보유분의 익절가가 **최근 종가 기준**이라 평단과 무관한 문제는 별건이다
  ([entry-holding-tp-ladder-20260913](entry-holding-tp-ladder-20260913.md) §8.3).
