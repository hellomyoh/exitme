# 챗봇에 KIS 부가 정보 도구를 붙일 것인가 (2026-09-15)

> 지시: "챗봇에 kis 부가 서비스 정보 호출해서 답변하도록 도구 만드는거 검토하세요."

**결론: 채택 권고. 도구 3개, 전부 읽기 전용·전역 시세 키·Redis 캐시. 구현 규모는 작다.**
단, 뉴스는 **제목만** 오므로 "원인 설명" 도구가 아니라 "무슨 일이 있었나" 도구다. 계약에 그 한계를 적어야 한다.

## 1. 오늘 실제로 호출해 확인한 것

| API | TR | 결과 | 쓸 수 있는 내용 |
|---|---|---|---|
| 종합 시황/공시 제목 `news-title` | `FHKST01011800` | 40건 | `hts_pbnt_titl_cntt`(제목) · 일시 · 제공사 · 분류코드. 종목코드 필터 가능. **본문 없음** |
| 투자자별 매매동향 `inquire-investor` | `FHKST01010900` | 30일 | 개인·외국인·기관 순매수 수량/금액 + 종가·전일대비. 예: 09-15 TIGER 200 외국인 +231,504주 |
| 업종/지수 현재가 `inquire-index-price` | `FHPUP02100000` | KOSPI200 | 1042.46 (−0.80%) · 상승 49 / 하락 149 종목 · 거래량 |

분류코드 `01`(뉴스)·`04`(공시)는 **표본에서 추정**한 것이다 — KIS 문서로 대조해야 한다.
셋 다 전역 시세 키(`settings.kis_*`)로 호출했고, 22:37 발급분 토큰 캐시를 읽어 새 발급 알림은 없었다.

## 2. 지금 챗봇의 구조 (그대로 얹을 수 있다)

- 도구 = OpenAI tools 스키마(`chat.TOOLS`), 실행 = `_run_tool(name, args, user_id, is_admin)` 의 `if name == …` 분기.
  실패는 `{"error": …}` 로 모델에 돌아가고, `CORE_CONTRACT` 가 "error 를 숨기지 말라"를 강제한다.
- 도구는 전부 **읽기 전용**이고 그 계약이 이미 명시돼 있다. 부가 정보 도구도 같은 부류다.
- 권한: 일반 사용자에게는 `algorithm_params` 만 감춘다. 뉴스·투자자·지수는 공식 유추 소재가 아니라 **일반에게도 열 수 있다.**
- LLM 은 OpenRouter 1회 호출(`_openrouter_call`)이고 테스트는 이걸 monkeypatch 한다 — 새 도구도 같은 방식으로 검증 가능.

## 3. 설계

### 3.1 도구 3개

| 도구 | 인자 | 반환(요약) | 캐시 |
|---|---|---|---|
| `market_news` | `code?`(생략 = 시장 전체), `limit?`(≤20) | `[{일시, 제목, 분류(뉴스/공시), 제공사}]` | 15분 |
| `investor_flow` | `code`, `days?`(≤10) | `[{일자, 종가, 전일대비, 개인·외국인·기관 순매수 수량/금액}]` | 장중 30분 · 장 마감 후 다음 16:05 까지 |
| `market_index` | `code?`(기본 `2001` KOSPI200; `0001` KOSPI, `1001` KOSDAQ) | `{지수, 전일대비, 등락률, 상승/하락 종목수, 거래량}` | 장중 60초 · 장외 30분 |

출력 필드는 **한국어 키**로 바꿔 준다(`frgn_ntby_qty` → `외국인_순매수_수량`). 모델이 KIS 약어를 해석하다 틀리는 일을 막는다.

### 3.2 호출 경로

- `KisClient` 에 정식 메서드 3개(`fetch_news_titles` · `fetch_investor_flow` · `fetch_index_price`)를 둔다. 챗봇이 `_get` 을 직접 부르지 않는다.
- 자격: **전역 시세 키**. 계좌 키를 쓰지 않으므로 계좌번호가 도구 경로에 등장하지 않는다.
- 대화형이라 `KisAuth(wait_on_rate_limit=False)` — 분당 제한이면 65초 자지 않고 즉시 `{"error"}`.
- **09:01 실행 중이면 양보**: `autoexec.is_running()` 이면 호출하지 않고 "무인 실행 중 — 잠시 후" 를 돌려준다. `poll_quotes` 와 같은 규칙(2026-09-09 유량 사고).
- Redis 캐시(`chat:kis:{tool}:{code}:{day}`) — 같은 질문을 되물어도 KIS 를 다시 부르지 않는다. 캐시 실패는 조용히 통과(호출로).

### 3.3 계약 문구 추가 (`OPERATIONS_KNOWLEDGE` / `CORE_CONTRACT`)

- "뉴스·공시는 **제목만** 제공된다. 제목으로 등락의 **원인을 단정하지 않는다** — '관련 제목이 이런 것이 있었다'까지만."
- "투자자 동향·지수는 **참고 정보**다. 이를 근거로 주문 수량·가격·시점을 바꾸라고 **권하지 않는다.** 전략은 이 정보를 쓰지 않는다."
- 이 두 줄은 이 프로젝트가 측정으로 확인한 사실의 연장이다 — 시가를 완벽히 알아도 47%p 손해, 방향을 알아도 66%p 손해. 부가 정보는 **사람의 이해**를 돕고 알고리즘에는 닿지 않는다.

## 4. 위험과 대응

| 위험 | 대응 |
|---|---|
| 유량(EGW00201) | 대화형 + 캐시라 하루 수 건. 08:45~09:15 는 `is_running()` 양보. 장중 폴링과 겹치지 않음 |
| 토큰 발급 알림 | 전역 키의 토큰을 07:00 워밍이 데운다(v0.32.0, **배포 필요**). 로컬 개발 환경은 별개 캐시라 개발 중 호출은 알림을 낸다(2026-09-15 확인) |
| 환각 — 제목으로 원인 지어냄 | 3.3 계약 + 도구 설명에 "제목만" 명시 |

| 비용 | 도구 결과 1~3KB. 뉴스 20건·동향 10일로 상한 |

## 5. 테스트 계획

- 단위: 가짜 클라이언트로 3개 도구의 **반환 형태**(한국어 키·상한·분류 매핑) · 캐시 적중 시 KIS 미호출 · `is_running()` 양보 · KIS 예외 → `{"error"}`.
- 통합: `_openrouter_call` monkeypatch 로 모델이 `market_news` 를 부르는 루프 1건(기존 `test_chat_tool_loop_and_final` 패턴).
- 일반 권한 세션에서 세 도구가 **보이는지**(`algorithm_params` 만 감춰야 한다).

## 6. 함께 검토했지만 이번엔 넣지 않는 것

- **VKOSPI·프로그램매매·신용잔고** — 제공은 되지만 오늘 호출로 확인하지 않았다. 필요 시 같은 방식으로 추가.
- **체결 도달 빈도(`fill_odds`)** — KIS 가 아니라 우리 분봉 데이터(1차 33.3% · 2차 13.5% · 3차 3.7%, 2026-09-15 측정). 유용하지만 이 건의 범위(KIS 부가 정보) 밖이라 별건.
- **뉴스 본문** — KIS 에 없다. 필요하면 외부 뉴스 소스가 새로 들어와야 하고, 그건 비용·의존성 결정이라 별도 판단.

## 7. 구현 규모

`kis_client.py` 메서드 3개 · `chat.py` 도구 정의 3개 + 분기 3개 + 캐시 헬퍼 1개 + 계약 2줄 · 테스트 1파일. 새 표·마이그레이션 없음.
새 동작이므로 **마이너**(0.34.0). 지시가 있으면 구현한다.
