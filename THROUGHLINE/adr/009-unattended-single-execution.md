# ADR-009 — 무인 매매 단일 실행: 설정 플래그만 참조, 09:01 에 계산·발주·동결

- 상태: 채택 (2026-09-08, 사용자 지시·결정)
- 관련: [ADR-008 (무인)](008-controlled-auto-execution.md) 을 **부분 대체** · [feature-portfolio §5](../features/feature-portfolio.md) · [docs/auto-execution-20260906.md](../docs/auto-execution-20260906.md)

## 배경

ADR-008 은 "사람이 승인한 줄만 09:01 에 낸다"로 출발해, 2026-09-07 에 승인을 16:45 배치가 대신하는 **완전 무인**이 덧붙었다. 사람의 승인은 사라졌지만 승인 → 실행의 **2단계 구조**는 남아 배치 7개(16:45 승인·08:40 보완·08:57 사전 갭 취소·09:01 발주·15:45/17:10 동기화·16:40 스냅샷), 스위치 2겹(계좌 허용 + 포트 완전 무인), 재대조 3종(승인 시·실행 시 계획 재대조·계좌 스위치 재검사)이 생겼다.

2026-09-08 아침 사고: 16:45 에 `approved` 된 그리드 매수 3줄이 09:01 에 발주되지 않았는데(배치 미실행 — beat 또는 워커 큐, 로그 없음) 화면은 "🤖 무인 승인" 만 보여 사용자가 장중에야 알았다. 같은 날 사용자 지시:

> 1. 매수/매도 수량은 실시간 반영(자본금 입출금이 있을 수 있으므로) 2. 무인매수 대기 상태 vs 아닌 상태를 명확히 표기 3. 무인매수/매도는 설정의 on/off 플래그만 참조해서 동작, 주문표의 버튼은 모두 제거, 설정에서 해제하면 즉시 동작 4. 무인매수/매도를 취소하고 수동 입력할 수 있는 취소 버튼 추가

## 결정

> **무인 매매는 실행일 09:01 에 한 번, 그 순간의 원장·설정으로 주문표를 계산해 곧바로 발주하고, 그 결과를 그날의 주문표로 동결한다. 통제는 증권사 계좌의 매수/매도 플래그 하나다.**

사용자 결정 4건 (2026-09-08):

| 질문 | 결정 |
|---|---|
| 시장가 줄(레버리지 진입·청산) | **09:01 시장가 무인 포함** — 갭 확인 뒤 시장가로 발주 (예약주문 경로 폐지) |
| 설정 해제의 의미 | **살아 있는 무인 주문도 즉시 취소** — 플래그를 끄면 그 방향의 오늘 미체결 무인 주문을 증권사에서 취소 |
| 플래그 위치 | **계좌별** `broker_credentials.auto_exec = {buy, sell, daily_buy_cap_pct}` — 포트의 '완전 무인 운영' 토글 제거 |
| 09:01 현금 원천 | **앱 원장 + 매수가능조회** — 원장(09:00 전 등록한 입출금 포함)으로 수량 계산, 발주 직전 KIS 매수가능조회로 미수 차단 |

### 1. 동결 기준을 '날짜'에서 '시각'으로

| 시점 (실행일 기준) | 주문표 |
|---|---|
| 09:00 전 | **실시간** — `_state_before(cutoff = 실행일 09:00 KST)` 로 그 순간까지 등록된 입출금·체결 모두 반영. 조회마다 스냅샷 갱신 |
| 09:01 | 실행기가 같은 함수로 계산 → 발주 → `PortfolioPlan.payload` 를 `frozen_at` 과 함께 **동결** |
| 09:00 이후 | 재계산하지 않고 동결 스냅샷의 `orders`·`account` 를 표시 (`frozen: true`). 이후 등록은 다음 주문표부터 |

B안(2026-09-02, "실행일 당일 등록은 당일 주문표 불변")의 목적 — HTS 주문장과 화면 불일치 방지 — 은 유지된다: 09:01 에 나간 주문이 곧 화면이다. 바뀐 것은 "당일 00:00" 이 "당일 09:00" 이 된 것뿐이다. 미국(TF·LTM) 경로는 무인 대상이 아니므로 종전 날짜 기준을 유지한다.

### 2. 단일 실행 절차 (`app/autoexec.py` `run_auto_execution`, 09:01)

연결 계좌가 있는 국내 포트마다:

1. 하루 1회 락(Redis `autoexec:{pid}:{date}` + `params.auto_exec.last_run.date`)
2. **주문표 계산** `_portfolio_orders(force_freeze=True)` → 스냅샷 동결 (플래그와 무관하게 — 수동 포트도 09:00 상태로 동결)
3. 실행일 검증 — 계산된 `exec_day` 가 오늘이 아니면 발주하지 않고 사유 기록("기준일 이후 일봉 누락 또는 휴장 미등록")
4. 게이트 — 정지(`paused`) · 사용자 취소(`skip.date == 오늘`) · 계좌 플래그 모두 꺼짐 → 발주 없이 상태 기록
5. 줄마다 `BrokerOrder(mode=auto)` 생성. 꺼진 방향의 줄은 `skipped`("무인 매도 꺼짐 — 수동")
6. **시가** 조회 → `gap_cancel_exact` 이하면 그리드 매수 `skipped_gap`
7. **잔고** 조회 → 원장 보유 vs 계좌 보유 불일치면 전부 생략 + 정지 · 매도 수량 ≤ 보유
8. **하루 매수 상한** (계좌 `daily_buy_cap_pct`, 기본 20%, 분모 = 주문표 `account.equity`) — 초과분은 **정지가 아니라 축소**: 남은 예산에 맞춰 수량을 줄이고(시장가는 최근 종가로 환산) 0 이 되면 생략. 신규 진입이 며칠에 걸쳐 채워진다
9. 발주 — 매도 먼저(시장가 → 지정가), 매수는 시장가(레버리지 진입) → 얕은 그리드 → 깊은 그리드. 매수 줄은 직전에 **매수가능조회**, 가능 수량이 계획보다 적으면 그 수량으로 축소(0 이면 생략)
10. 결과 `last_run` + 활동 로그 + 알림. 연속 실패 2회 → 정지

폐지: 16:45 자동 승인 · 08:40 보완 · `approved` 상태 · 실행 시 계획 재대조(실행기가 계산 주체) · 시장가 예약 접수 · 08:57 사전 갭 취소(모듈은 남기되 배치·설정에서 제외 — 무인 줄은 09:01 실제 시가로 판정하므로 불필요) · 포트별 완전 무인 토글 · 하루 상한 초과 시 정지.

### 3. 상태 표기 (요청 2) — `auto_exec_view().state`

| code | 화면 | 조건 |
|---|---|---|
| `off` | 수동 모드 — 무인 꺼짐 | 계좌 없음 또는 매수·매도 모두 꺼짐 |
| `paused` | ⛔ 정지 — {사유} | `params.auto_exec.paused` |
| `skipped_user` | 무인 취소됨(수동) — {실행일} | `skip.date == exec_day` |
| `waiting` | 🤖 무인 {매수·매도} 대기 — {실행일} 09:01 발주 예정 | 플래그 켬 · 실행 기록 없음 · 09:00 전 |
| `ran` | ✅ 발주 {n}건 · 갭 생략 · 생략 · 실패 · 시가 | `last_run.date == exec_day` |
| `missed` | ⚠️ 09:01 실행 기록 없음 — 09:15 감시가 지연 실행 | 실행일 오늘 · 09:05 이후 · 기록 없음 |

각 상태에 사유가 붙는다. 주문표 표의 '무인' 열은 줄별 최종 상태(발주됨 #번호 · 체결 · 생략 사유 · 갭 생략 · 실패 · 취소됨)만 읽기 전용으로 보인다.

### 4. 버튼 (요청 3·4)

주문표에서 제거: 선택 주문 등록 · 무인 실행 승인 · 전체 선택 · 증권사 상태 새로고침 · 완전 무인 설정/지금 승인 실행/전량 취소/무인 중지 · 줄별 취소. 남는 것:

- **이번 실행일 무인 취소 → 수동** `POST /portfolio/{pid}/auto-exec/skip {date}` — 09:00 전이면 그날 발주를 건너뛰고, 09:01 후면 살아 있는 무인 주문을 증권사에서 취소한다. 다음 실행일에 자동 복귀. 09:00 전에는 **되돌리기** `POST …/auto-exec/unskip` 가능
- 정지 배너의 **다시 켜기**(기존)
- 체결 등록(일지 입력 — 무인과 무관하므로 유지)

설정 › 무인 실행의 계좌 플래그를 끄면 서버가 오늘 접수된 그 방향의 무인 주문을 취소하고 건수를 돌려준다(사용자 결정). 켜면 다음 09:01 부터 동작한다 — 별도 승인·즉시 실행 단계가 없으므로 "해제하면 즉시" 가 자연히 성립한다.

### 5. 감시 (사고 재발 방지)

- **파이프라인 하트비트** — beat 가 60초마다 `pipeline_heartbeat` 태스크를 보내고 워커가 Redis `autoexec:pipeline:heartbeat`(TTL 180초)를 갱신. scheduler·worker 컨테이너 헬스체크가 이 키를 확인한다 → beat 미발송·큐 미소비 모두 unhealthy 로 드러난다(종전 헬스체크는 모듈 import 만 확인)
- **09:15 워치독** `auto_exec_watchdog` — 무인 대상 포트에 오늘 실행 기록이 없으면 경고 로그·알림을 남기고 **지연 실행**한다(락·마커로 중복 발주 없음). 지정가는 같은 가격이므로 14분 지연의 비용은 그 사이 체결 기회 상실에 그친다

## 대안과 기각

- **2단계(승인→실행) 유지 + 보완 배치 강화**: 오늘 사고의 원인 후보(beat·큐)는 단계 수와 무관하게 남고, `approved` 가 화면에 "대기"로 오해되는 문제도 남는다. 기각.
- **상한 초과 시 정지 유지**: 레짐 전환일 신규 진입(총자산 30~40%)마다 정지 → 사람 개입이 매번 필요해 무인의 목적과 충돌. 축소로 대체.
- **입출금만 실시간, 체결은 날짜 동결**: 거래 종류별로 다른 동결 규칙은 설명이 어렵고, 09:00 시각 동결 하나로 두 요구가 모두 충족된다. 기각.
