# ADR-008 — 통제된 무인 실행: 승인된 지정가를 시가 확인 후 자동 발주

- 상태: 채택 (2026-09-06, 사용자 지시)
- 관련: [ADR-007](007-ravg-v25-adoption.md), [docs/broker-reserved-orders-20260905.md](../docs/broker-reserved-orders-20260905.md), [docs/auto-execution-20260906.md](../docs/auto-execution-20260906.md), [docs/krx-aftermarket-20260914-review.md](../docs/krx-aftermarket-20260914-review.md) §갭 취소

## 배경

RAVG 의 갭 취소 규칙("시가가 전일 종가 − 1.5×ATR 이하면 그날 그리드 매수를 내지 않는다")은 백테스트에서는 시가를 본 뒤 판정하지만, 실전은 전날 예약주문을 넣어 09:00 동시호가에 그리드 지정가가 들어가므로 갭이 나면 시가에 그대로 체결됐다. 시가는 09:00 에야 확정되어 "미리 취소"가 불가능하고, 예약주문 취소 창(~07:30)은 그 전에 닫힌다. 실전과 백테스트가 어긋나는 유일한 지점이었다(연 4회, CAGR 0.15%p·MDD 1%p 규모).

기존 원칙(2026-09-05): **자동(무인) 발주 없음** — 사용자가 주문표에서 버튼을 눌러 접수한 예약주문만.

## 결정

사용자 판단(2026-09-06): "무인 매수/매도가 철저히 통제된 환경에서 된다면 크게 문제는 없다." 원칙을 다음과 같이 바꾼다.

> **무인 발주는 사용자가 승인한 지정가 줄에 한해, 설정에서 허용한 방향(매수·매도 각각)만, 실행일 09:01 에 시가를 확인한 뒤 낸다.**

의사결정은 사용자에게 남고, 자동화되는 것은 "시가를 본 뒤 낸다"는 타이밍이다.

## 통제 조건 (모두 코드로 강제, `app/autoexec.py`)

| # | 조건 | 구현 |

| 3 | 지정가만 | 시장가 줄(레버리지 진입·청산)은 승인 거절 → 기존 예약주문 경로 |
| 4 | 시가 확인 후 발주 | 09:01 워커: 현재가 조회의 당일 시가 → 계획 스냅샷 `gap_cancel_exact` 이하면 그리드 매수 `skipped_gap`. 백테스트와 같은 순서 |
| 5 | 계획 일치·한도 | 줄이 서버 계획 스냅샷과 정확히 일치(수량 포함). 매수는 얕은 그리드(높은 지정가)부터 **발주 직전 KIS 매수가능조회**(주문가능현금·미수 없는 수량 — 증거금·매도대금 재사용 반영)로 가능 수량 ≥ 계획 수량인 줄만 발주, 부족한 줄은 생략(수량 축소 없음). 조회 실패 시 예수금 총액 누적 규칙으로 폴백. 매도 수량 ≤ 잔고, 국내 포트만 |
| 6 | 하루 1회·재시도 없음 | Redis 락 + `params.auto_exec.last_run.date` 마커, Celery 태스크 `max_retries=0` |

| 10 | 예약↔무인 상호 배제 | 같은 실행일의 같은 줄은 예약주문과 무인 승인 중 하나만 — 양쪽 접수 모두 상대의 활성 상태를 중복으로 본다(2차 검증에서 예약 쪽 구멍 수정) |
| 11 | 09:01 사전 대조 | 발주 직전에 **앱 원장의 전략 종목 보유(200 ETF·레버리지)와 계좌 잔고를 대조** — 다르면 그날 전부 생략하고 정지(주문표가 틀린 보유를 전제로 계산된 것이므로). 15:45 사후 대조를 기다리지 않는다 (사용자 지시 2026-09-06). 현금은 09:01 대조 대상이 아니다 — 결제 시차(T+2)로 오탐이 잦아, 15:45 동기화의 **예수금 대조**(원장 현금 vs 계좌 D+2 예수금, `app/cashcheck.py`)가 경고와 원클릭 보정만 제공한다 |
| 12 | 실행 시점 계획 재대조 | 승인 행의 줄 키·수량이 그날 계획 스냅샷과 같은지 발주 직전에 다시 확인 — 다르면 그 줄만 생략 |
| 8 | 감사 기록 | 발주·생략·실패를 `BrokerOrder` 에, 요약을 `params.auto_exec.last_run` 에. 주문표 표·배너·마지막 실행 요약 표시. **로그 페이지**(2026-09-06, `app/activity.py`, `/logs`): 거래 원장·주문 상태·실행/동기화 이벤트(정지·실패·조회 오류 포함)를 한 표에 합쳐 보여 준다. **텔레그램 알림**(2026-09-07, `app/notify.py`): 같은 이벤트를 카테고리(무인 실행 결과·자동 승인·사전 갭 취소·정지·동기화·예수금 대조·주문·체결 등록·일일 현황)로 걸러 사용자가 체크한 것만 발송 — 사람이 보지 않는 운영의 '정지된 채 모르는 상태' 위험을 줄이는 장치 |

| 14 | 완전 무인 운영 (자동 승인 + 전량 취소) | 사용자 지시(2026-09-07): "이 단계(승인) 없이 완전 무인으로 운영 · 이미 주문이 완료된 내역을 취소하는 기능". `app/autoapprove.py`: 포트별 `params.auto_exec.auto_approve = {enabled, market_reserve, daily_buy_cap_pct}` (기본 꺼짐; 켜려면 국내 포트·연결 계좌·설정에서 매수 또는 매도 허용 필요). 사용자 결정(2026-09-07): 레버리지 시장가 줄은 **예약주문으로 무인 접수**(옵션 기본 켬), 하루 매수 총액 상한은 **총자산 대비 % 로 옵션에서 지정, 기본 20%**(0 = 없음; 분모는 신호 기준일 총자산 `account.equity`, 시장가 줄은 최근 종가로 근사). 레짐 전환일의 레버리지 진입(총자산의 30~40%)은 20% 를 넘어 그날 정지될 수 있다 — 의도된 확인 지점. 16:45 배치 `auto_approve_plan`(체결 가져오기 15:45·일봉 16:05·스냅샷 16:40 뒤)가 다음 실행일 주문표를 계산·저장(`_portfolio_orders`)하고 허용 방향의 지정가 줄을 `approved` 로, 시장가 줄(레버리지)은 옵션이면 예약주문으로 접수(실전 계좌·접수 창 안). 정지 상태·설정 모두 꺼짐·실행일 지남(오늘 일봉 없음)·스냅샷 없음은 건너뛰고 로그. **하루 매수 상한**(선택) 초과 시 승인하지 않고 정지(배너). 09:01 통제(④~⑫)는 그대로. **전량 취소** `POST /portfolio/{pid}/orders/cancel-all` — 승인 철회·예약주문 취소 TR·발주된 정규 주문 취소 TR, `stop=true` 면 정지 + 자동 승인 끔(긴급 정지 버튼). 체결된 줄은 취소 불가(반대 매매만). 표의 승인·발주 줄에도 개별 취소 버튼 |
| 13 | 장 시작 전 예상 시가 갭 취소 (**취소만 무인**) | 사용자 지시(2026-09-06 밤): "무인 매수/매도는 수동으로 직접 지정한다(초기 기획안대로). 장 시작 전 예상 시가를 계산해서 특정 가격 이하시 그리드 매수를 전량 취소한다(취소는 무인으로)." — 08:57 워커(`app/preopen.py`)가 200 ETF **예상체결가**(호가/예상체결 TR FHKST01010200 `antc_cnpr`)를 읽어 갭 취소 기준(`gap_cancel_exact`) 이하면 KIS 정정취소가능(미체결) 주문 중 **200 ETF 매수이고 오늘 계획의 그리드 지정가와 같은 것**을 취소한다(앱 예약주문·HTS 직접 주문 모두, 그 외 주문은 건드리지 않음). 발주는 하지 않는다. 무인 승인 줄(09:01 실제 시가 판정)은 대상 외. 설정 `auto_exec.preopen_cancel` 기본 **켜짐**(취소만 하는 보호 동작 — 사용자 지시). 결과는 `BrokerOrder.status=gap_cancelled`, `params.preopen_cancel.last_run`, 로그 페이지. "대안과 기각 사유"의 첫 항목(예상체결가 취소)이 이로써 **병행 채택**된 것이다 — 09:01 발주는 무인 발주를 켠 사용자용, 08:57 취소는 예약주문·수동 주문 사용자용 |

## 대안과 기각 사유

- **예상체결가로 08:58 에 그리드만 취소**: 무인 동작이 취소에 한정되어 원칙 충돌은 작지만, 예상체결가는 근사값이고 정규 주문 취소 TR 도입은 마찬가지로 필요하다. 사용자가 무인 발주를 허용하기로 했으므로 백테스트와 정확히 일치하는 "시가 확인 후 발주"를 택했다. → **2026-09-06 밤 사용자 지시로 병행 채택**(통제 조건 13): 발주를 직접(예약주문·HTS) 넣는 운용에서는 이 취소가 갭 대응의 유일한 수단이다. 예상체결가가 근사값인 한계는 남는다 — 예상이 기준 아래인데 실제 시가가 위로 열리면 그날 그리드 매수를 놓치고(손실은 아님), 반대면 갭 체결이 그대로 난다(기존과 같음).
- **수동 절차(08:55 HTS 확인)**: 연 4회·0.15%p 라 감내 가능하지만, 사용자가 자동화를 원했다.

## 영향

- `KisTradingClient` 에 정규 주문 TR(현금 매수 TTTC0012U·매도 TTTC0011U, 취소 TTTC0013U; 모의 VTTC0802U/0801U/0803U) 도입. 호출자는 `app.autoexec` 와 취소 엔드포인트만.
- 워커 09:01 `auto_execute_open`(휴장일 스킵). 15:45/17:10 동기화가 무인 주문의 체결 상태를 확정하고 대조 경고 시 정지.
- 도입 단계: 모의투자(vps) 계좌로 1주 → 실계좌 소액 → 정상 운용 (각 단계 사용자 확인).
- 문서: feature-portfolio·broker-reserved-orders 의 "자동 발주 없음" 문구는 이 ADR 을 가리키도록 갱신.
