# ADR-013: 현금 부족 그리드 단은 생략이 아니라 축소한다 (정본 §6 구현 규칙 확정)

## 상태

Accepted (2026-09-13, 사용자 승인 "추가 이견이 없다면 구현을 진행하세요")

## 배경

정본 §6 은 그리드 3단의 **가격**(종가 × (1 − k·Grid))과 **예산 배분**(50/30/20)을 정하지만, 배분된 금액이
가용 현금을 넘을 때 어떻게 할지는 정하지 않는다. 구현은 그 단을 통째로 건너뛰었다(`planner.py` 그리드 루프의
`if qty <= 0 or qty * price > cash_left: continue`).

그 결과가 단순한 "덜 사기"가 아니라는 점이 이번 검토에서 드러났다. 예산이 50/30/20 으로 갈려 있으므로
**1단(50%)이 현금을 넘으면 1단이 통째로 빠지고, 더 작은 2단(30%)·3단(20%)만 나간다.** 같은 현금이 더 깊은(싼)
가격으로 배정되는 셈이다. 실측(2018-01-26~2026-09-10, 자본 1억):

| 일자 | 종전 | 변경 후 |
|---|---|---|
| 2020-09-22 (현금 384만) | `grid2 81주` + `lev_tact1 97주` | `grid1 126주` |
| 2020-09-24 (현금 346만) | `grid3 106주` + `lev_tact2 27주` | `grid1 116주` |

8.6년 2,104 계획일 중 **78일**이 이 분기에 걸린다.

## 결정

현금이 모자라는 단은 **가용 현금이 감당하는 수량으로 축소**해 발주한다. 수량은 수수료를 포함해 계산한다.

```
qty = floor(remaining × w_k / L_k)
if qty ≤ 0: 그 단 없음
if qty × L_k > cash_left:
    qty = floor(cash_left / (L_k × (1 + 수수료율)))     # 축소
    if qty ≤ 0: 그 단 없음
cash_left -= qty × L_k        # ← 위치 불변: 축소분이 현금을 먼저 차감한다
주문 추가                      # ← 위치 불변
```

현금 차감과 주문 추가는 **원래 위치를 유지**한다. 그래야 축소된 단이 현금을 먼저 잡고, 뒤따르는 단과
레버리지(전략·전술)가 남은 현금에 맞춰 조정된다. 가격·단수·배분 가중·레짐 규칙은 **모두 불변**이다.

## 근거

**이것은 오류 수정이 아니라 배분 정책의 선택이다.** "큰 단을 건너뛰고 작은 단을 낸다"도 일관된 규칙이었다.
바뀌는 것은 같은 현금을 **얕은(비싼) 가격에 먼저 쓰는가**이다. 채택 근거는 둘:

1. **계획과 실행의 원리 일치** — 실전 실행기는 이미 KIS 매수가능조회 결과로 수량을 축소해 발주한다(ADR-009 §2-8·9).
   플래너만 생략하면 같은 상황에서 계획과 실행이 다른 규칙을 쓴다.
2. **과거 표본에서 소폭 유리** — 8.6년 누적 292.24% → 295.08%(+2.84%p), MDD −22.67% → −22.61%, 샤프 1.049 → 1.053.
   1년 창 89개 짝 비교에서 이김 51 · 짐 17, 두 자산곡선 일수익 차이의 블록 재표집(5~252일) 90% 구간 하한이 모두 0 위.

**이 근거의 한계를 명시한다.** +2.84%p 는 이 표본·재표집 가정에서 관측된 작은 차이일 뿐 미래 우월성이나
손실·위험 비악화를 보장하지 않는다(89창 중 **17창에서는 더 나빴다**). 블록이 길어질수록 구간 하한은 0 에 접근한다(+0.0001).

## 알려진 성질 (과장하지 않기 위해 기록한다)

- **예산 보장의 범위** — 이 표본에서 수수료 포함 매수 총액이 *계획 가격 기준으로* 현금 + 축소 매도대금을 넘은 날은
  없다. 그러나 **일반적 보장이 아니다**: 이 분기는 원금이 현금을 넘을 때만 수수료를 고려하고, 예약은 원금만 차감하며
  (`cash_left -= qty × L_k`), 실제 체결가·매도대금 변동은 검사 범위 밖이다. **현금버퍼(자기자본 0.5%)까지 보존하지는
  않는다** — 변경 후 2일·최대 1,692원, 변경 전에도 1일·3,136원으로 **기존 성질**이다. 모든 주문의 수수료를 예약하는
  것은 별개 변경이며 따로 검증해야 한다.
- **주문선 체결률** — 계획 매수 주문 대비 체결은 그리드 기준 10.94% → **11.62%** 로 올랐다. 다만 분자(체결 234→237)보다
  **분모(계획 2,138→2,039)의 기여가 크다** — 축소된 단이 현금을 다 쓰면 뒤 단이 계획되지 않기 때문이다. 전체 체결
  건수는 600 → 599 로 사실상 불변이다. 체결이 늘어서 유리하다는 주장은 하지 않는다(`fill-rate-study-20260912.md`:
  체결률을 크게 올린 변형들은 오히려 수익이 나빴다).
- **배분 이동** — 8.6년 매수 체결 구성 grid1 183→185 · grid2 41→42 · lev_tact1 28→**25** · lev_tact2 13→14.

## 검토했으나 채택하지 않은 것

- **레버리지 우선 배분**(그리드 예약 전에 레버리지 수량 결정, A3): 14일만 바뀌고 현행 대비 −0.56%p, 짝 재표집 90%
  구간 −0.0064~+0.0033 로 구분되지 않는다. 추가 복잡성을 정당화할 근거가 없다.
- **생략 유지 + 레버리지 우선**(A3+이전): 291.67%, 구간 전체 음수. 상대 열위.

## 영향

- `apps/api/app/strategy/planner.py` 그리드 루프 3줄. 백테스트·일일 시그널·09:01 실행기가 같은 플래너를 쓰므로
  세 경로에 동시에 적용된다.
- 과거 주문표(동결 스냅샷)는 바뀌지 않는다. 새 계획부터 적용된다.
- 연구 스크립트 `scripts/entry_alloc_study.py` 의 기준선이 이 규칙이 되고, `legacy_skip=True` 가 채택 전 규칙을 재현한다.
