# ADR-014: 코어 로트 익절을 사다리로 나눈다 (정본 §5.6 근사 규칙 개정)

## 상태

Accepted (2026-09-13, 사용자 승인 "사다리 구현을 진행하세요")

## 배경

정본 §6 의 익절은 **로트별**이다 — 그리드 체결분은 `체결가 × (1 + 체결일 Grid)` 를 로트에 얼려 둔다. 그런데 두 종류의
로트는 자기 체결가를 익절 기준으로 쓸 수 없다.

- **보유분 입력으로 시작한 로트** — 전략이 산 것이 아니라 사용자가 등록한 것이라 '체결일 Grid' 가 없다.
- **상승장 체결분(core)** — 상승장에는 익절을 붙이지 않고(f1), 중립 전환일에 비로소 익절가를 받는다.

이 로트들은 `plan()` 의 core 분기에서 **오늘 종가 × (1 + Grid)** 한 가격을 받았고, 로트가 하나면 **전량이 한 줄**로 나갔다.
사용자 지적: "보유 수량이 있는 상태로 시작하면 분할 매도가 안 된다."

2026-09-03 검토는 **평단 역계산으로 로트를 쪼개는 안**을 기각했다(평단 < 종가면 익절가가 이미 도달 → 즉시 전량 매도).
이번 결정은 평단을 건드리지 않고 **주문 수량만** 나눈다.

## 결정

core 로트의 익절을 **매수 그리드의 거울**로 나눈다.

```
가격  P_k = 호가올림[ 종가 × (1 + k · Grid) ]      k = 1 … grid_steps (3)
수량  grid_weights(50/30/20) 비율, 최대잔여법으로 정수 배분
      · 합계 = 축소 선점을 뺀 available (수량 유실·초과 없음)
      · 잔량은 잔여가 큰 단부터, 동률이면 가까운 단 — 1주면 1단(가장 잘 닿는 가격)
      · 빈 단은 만들지 않는다
```

**그리드 로트는 대상이 아니다.** 체결가에 묶인 익절가가 정본 규칙이고, 거기에 손대면 모델 자체가 바뀐다.
축소(`reduce`)의 FIFO 선점·밴드 규칙, 레짐 전환 시 로트 재분류는 모두 불변이다.

## 근거

시작일 89개 × 1년 짝 비교(현금 40% + K200 60% 보유로 시작, core 익절만 교체):

| | 평균 차이 | 중앙 | 최악 | 이김 : 짐 : 동일 | 전량(≥99%) 매도 비중 |
|---|---|---|---|---|---|
| 채택 전 (한 가격 전량) | — | — | — | — | **57%** |
| **채택 (사다리 50/30/20)** | **+0.245%p** | +0.077%p | −1.260%p | **46 : 18 : 25** | **42%** |

MDD 평균 −12.35% → −12.28% 로 사실상 불변. 보유 비중 30%·60%·100% 에서 부호·승패가 같다.

기전은 **윗단이 드물게만 체결된다**는 데 있다 — 다음날 고가가 종가×(1+k·Grid)에 닿는 빈도가 1× **28.4%**, 2× 5.3%,
3× 1.1%. 그래서 실질 효과는 "작은 급등에 절반만 팔고 나머지는 들고 간다"이고, 전량 매도가 57% → 42% 로 내려간다.

**"덜 파는 것"만이 이유는 아니다.** 절반만 팔고 나머지를 영구 보유하는 변형은 34:30 으로 승률이 크게 낮다.
윗단을 실제로 걸어 두는 쪽(46:18)이 낫다.

## 한계 (과장하지 않기 위해 기록한다)

- 이득은 **연 +0.25%p** 로 `validation-methodology-20260913.md` 의 노이즈 밴드 안이다. **미래 우월성을 보장하지
  않는다** — 89창 중 **18창에서 더 나빴다**.
- 표본이 상승 편향 구간을 포함해 "덜 파는" 변형이 유리하게 나올 소지가 있다.
- 채택 근거의 무게는 성과가 아니라 **"근사치인 익절가를 한 가격에 몰지 않는다"** 는 행동의 타당성에 있다.
- 익절가가 여전히 **오늘 종가 기준**이라는 근사는 그대로다. 사다리는 그 근사를 더 잘 배치할 뿐 없애지 않는다.
  평단과의 관계(평단 미만 가격에 나가는 매도를 '익절'로 부르는 문제)는 **별건**이다.

## 검토했으나 채택하지 않은 것

- **기준가 고정(P₀·g₀) + 단별 잔여 상태 유지** (2026-09-13 사용자 제출 보고서 안): 평균은 비슷하나 승률 **32:31**,
  전량 비중 **55%** 로 현행(57%)과 거의 같아 문제를 해결하지 못한다. P₀ 아래로 내려가면 오래 안 팔리다가 회복 시
  세 단이 한꺼번에 체결된다.
- **수량 고정 + 가격 매일 갱신(L7)**: 평균 +0.422%p·최악 −0.464%p 로 이 표본에서는 더 낫지만(이김 40 : 짐 21),
  **단별 잔여 수량을 저장해야 한다** — 지금 플래너는 원장에서 매일 다시 계산하는 순수 함수다. 상태를 도입하면
  부분체결·재시작·수동 매도마다 새 실패 모드가 생긴다. **연 +0.18%p 차이가 그 복잡성을 정당화하지 않는다.**
  재검토 조건: 실전에서 사다리 체결이 쌓여 단별 진행을 저장할 이유가 따로 생길 때.
- **촘촘한 사다리(1·1.5·2×Grid)**: +0.170%p, 39:18 — 현행 배치보다 못하다.

## 실사용에서 드러난 누락과 보완 (2026-09-13, 같은 날)

배포 전 실제 주문표(TIGER 200 400주 보유, 중립장)를 확인하니 **익절이 여전히 전량 한 줄**이었다. 원인은 배포 지연이
아니라 **적용 범위의 누락**이다.

`lots.rebuild_lots` 는 태그 없는 K200 로트를 **상승장이면 `core`, 그 밖에는 `grid` + 근사 익절가**로 되살렸다.
사다리는 `core` 에만 걸리므로, **중립장에서 보유분 입력 로트는 `grid` 가 되어 사다리를 받지 못했다.** 백테스트는
`initial_lots` 를 `core` 로 만들기 때문에 이 차이가 측정에 드러나지 않았다 — 0027 감사가 지적한 "백테스트와 실전의
로트 재구성이 갈리는" 문제와 같은 종류다.

**보완**: 태그 없는 K200 로트는 **레짐과 무관하게 `core`(익절가 미고정)** 로 되살린다. 익절가는 플래너가 그날 종가로
만들며, **1단이 종전 근사가와 같아** 가장 가까운 가격은 보존된다.

```
400주 보유 · 종가 109,735 · Grid 2.5%
  종전  익절 400주 @ 112,480                      (한 줄)
  현행  익절 200주 @ 112,480 · 120주 @ 115,225 · 80주 @ 117,970
```

`approx_tp` 인자는 더 쓰지 않는다(하위 호환으로만 남김).

## 영향

- `apps/api/app/strategy/planner.py` — core 익절 분기 + `_core_tp_ladder` 헬퍼. 백테스트·일일 시그널·09:01 실행기가
  같은 플래너를 쓰므로 세 경로에 동시에 적용된다.
- 주문표에 익절이 최대 3줄로 보인다(가격이 달라 표시 병합에 걸리지 않는다). 주문 종류는 `tp` 그대로라
  체결 귀속(`lots.sell_tag` — 익절가로 로트를 찾는다)과 실행기 `line_key` 는 손대지 않았다.
- 과거 동결 주문표는 바뀌지 않는다. 새 계획부터 적용된다.
