# 1. 프로젝트 기본 정보

## 프로젝트명

**StockLab** (가칭) — 백테스트 + 실전매매 기록 + 자산 대시보드 통합 웹

## 프로젝트 목적

확정된 매매 전략 **RAVG v2**(레짐 적응형 변동성 그리드, `trade_algorithm_final.md`)를
**검증(백테스트) → 실행(일일 시그널·실전매매 기록) → 관리(대시보드)** 하는 하나의 루프로 제공하는 웹 시스템.

## 대상 사용자

국내 주식(ETF) 개인 투자자 중 전략 검증에 관심 있는 중급 사용자. 초기에는 운영자 본인 중심의 소수 사용자.

## 핵심 가치

1. **전략이 내장된 시뮬레이터**: 범용 조건식 백테스트에 더해, RAVG v2가 기본 전략 프리셋으로 내장되어 즉시 검증·운용 가능
2. **일일 주문표 자동 생성**: 매일 종가 기준으로 레짐·노출·그리드를 계산해 다음 거래일 지정가 주문표를 제시
3. **정직한 수치**: 수수료·세금·슬리피지·시세 지연을 숨기지 않고 상시 표기

## 산출물 작성 언어

한국어 (코드 식별자·커밋 메시지는 영어)

## 성공 지표

백테스트 1회 이상 실행 유저 60% / 백테스트→실전 포트 전환율 20% / 주간 재방문 40%

# 2. 프로젝트 설명

KODEX 200·KODEX 레버리지를 대상으로 한 매매 전략 RAVG v2를 중심에 둔 개인 투자자용 웹 서비스.

- **차트**: HTS 수준의 캔들 차트 + 지표·드로잉 (TradingView Lightweight Charts v5)
- **시뮬레이터**: 조건 설정 → 실행(진행률) → 결과의 3스텝 위저드 백테스트. RAVG v2 프리셋 및 절제(ablation) 비교 지원
- **전략 엔진**: 장 마감 후 배치로 지표→레짐→노출→주문표를 계산·저장하고 화면에 제시 (실주문 아님, v1 범위 외)
- **실전매매 기록**: 수동 매수 등록 기반 수익률 추적 (매수 시점 기준)
- **대시보드**: 총자산 히어로 수치 + 벤토 그리드, 현재 레짐/노출 게이지 포함

**v1 범위 외**: 증권사 실주문 체결, 파생·해외주식, 소셜/커뮤니티

# 3. 핵심 기능

## MVP에 반드시 포함할 기능

1. **시세 데이터 파이프라인**: KIS Open API + pykrx로 일봉·분봉 수집, TimescaleDB 하이퍼테이블 정규화 저장(차트·백테스트·실전이 동일 데이터 사용), 수정주가 적용, 장 마감 후 배치 + 장중 폴링/WS
2. **주식 차트 (HTS 수준)**: 캔들/바/라인/Heikin-Ashi, 1분~월봉, 멀티 페인(MA·볼린저·일목·VWAP / 거래량·RSI·MACD·스토캐스틱·OBV·수급), 드로잉 저장, 5만 캔들 60fps, 매수/매도 마커·평단선 오버레이
3. **백테스트 3스텝 위저드**: §7 화면 흐름 참조. 비동기 잡 + WS 진행률, KPI(총수익률·CAGR·MDD·샤프·승률·손익비·거래횟수), 자산곡선 vs KOSPI, 월별 히트맵, underwater 차트, 거래내역 CSV, 최대 5개 전략 오버레이 비교
4. **RAVG v2 전략 엔진** (본 프로젝트 차별점, `trade_algorithm_final.md`가 명세 정본):
   - 백테스트 내장 프리셋: RAVG v2 전체 + 절제 테스트용 모듈 on/off 플래그 (동 문서 §11 검증 계획의 5개 모듈)
   - 일일 시그널 배치: 종가 확보 → 지표(MA/EMA/ATR/σ/σ_down) → 레짐 판정 → E·w_200·w_LEV 계산 → 다음 거래일 지정가 주문표 생성·저장
   - 주문표 화면: 오늘의 레짐·목표 노출·그리드 가격·수량, 갭 필터/강제청산 조건 안내, 계산 근거(지표값) 열람
5. **실전매매 기록**: 매수 등록(종목·수량·단가·일시, 차트 클릭 입력), 평단 자동 재계산, 매수 시점 기준 수익률 카드(비용 포함/제외 토글, 보유일수·연환산·최고최저 도달·목표/손절 진행 바), 계좌 수준 TWR/XIRR, 매매일지 메모·태그
6. **대시보드**: 총자산 히어로 + 전일대비, 자산 구성 도넛(주식/현금/기타 수동 등록), 보유 종목 테이블, 자산 추이(1M~전체), 일간 손익 캘린더 히트맵, 포트 성과 비교, **현재 레짐·노출 게이지(RAVG v2)**, 시세 기준시각 상시 표기
7. **백테스트→실전 전환**: 결과 화면에서 동일 파라미터로 실전 포트 생성

## 후순위 기능

- 차트 리플레이 모드(바 단위 전진 재생 수동 연습)
- 목표·손절 도달 브라우저 푸시 알림
- 파라미터 스윕 자동화(그리드 서치)
- 다계좌·가족 계정

# 4. 사용자 시나리오

1. **전략 검증**: 사용자가 시뮬레이터에서 RAVG v2 프리셋 선택 → 기간·자본금 설정 → 실행(진행률 확인) → KPI·자산곡선을 KODEX 200 매수보유 벤치마크와 비교 → 절제 플래그를 바꿔 재실행해 모듈별 기여 확인
2. **일일 운용**: 장 마감 후 엔진이 주문표 생성 → 사용자는 주문표 화면에서 내일의 지정가 매수/매도 목록과 레짐 근거를 확인 → 본인 증권사 HTS에서 수동 발주 → 체결분을 실전매매 메뉴에 등록
3. **성과 관리**: 대시보드에서 총자산·레짐 게이지·손익 캘린더 확인, 실전 포트 vs 백테스트 기대 성과 비교
4. **차트 분석**: 종목 차트에서 지표·드로잉으로 분석, 매수 시점 마커와 평단선으로 포지션 복기

# 8. 기술 조건

## 희망 기술 스택

| 계층 | 스택 |
|---|---|
| 프론트 | Next.js 15 + TypeScript + Tailwind v4 + shadcn/ui, TradingView Lightweight Charts v5 (Apache-2.0, 지표 자체 구현) |
| API | FastAPI (python 3.12) + SQLAlchemy + Pydantic v2, REST + WebSocket |
| 워커 | Celery worker (백테스트, pandas/vectorbt) + Celery Beat (시세 수집·일일 시그널 배치) |
| 저장소 | PostgreSQL 16 + TimescaleDB / Redis 7 (캐시·브로커·Pub/Sub) |
| 인프라 | Nginx 리버스 프록시, docker compose (dev/prod override 분리), GitHub Actions CI에서 동일 compose로 e2e |

## 반드시 지켜야 할 제약사항

- 조회(API)와 계산(worker) 분리 — 백테스트 장시간 작업이 UI를 막지 않을 것. 진행률·결과는 Redis Pub/Sub → WS 스트리밍
- 시세 원본은 TimescaleDB 1곳 정규화 — 차트·백테스트·실전·전략 엔진이 동일 데이터 사용
- **백테스트 정합성: 종가 신호 → 익일 체결, look-ahead 방지, 수정주가 적용, 거래정지·상폐 처리** (RAVG v2 규칙과 동일)
- 백테스트 엔진과 일일 시그널 엔진은 **동일한 전략 코드**를 공유할 것 (검증된 로직이 그대로 운용에 사용됨)
- 환경변수 `.env` 단일 관리 + `.env.example` 커밋, 전체 기동 `docker compose up -d` 한 줄
- 모의·과거 데이터 기반이며 투자 권유가 아님을 시뮬레이터·실전·주문표 화면에 명시

# 10. 횡단(아키텍처) 기준선

## 데이터 모델 공통 규칙

- 시계열은 TimescaleDB 하이퍼테이블, 그 외 정규화 테이블. 금액은 정수(원), 비율은 decimal. 모든 테이블 `created_at`/`updated_at`
- 시그널·주문표는 불변 이력으로 append-only 저장 (재계산 시 새 버전 생성)

## 네이밍 규칙

- Python: snake_case / TS: camelCase / 테이블·컬럼: snake_case / API 경로: 복수 명사 (`/backtests`)

## API 계약 스타일

- REST(JSON, Pydantic 스키마 단일 정의) + WebSocket(`/ws/quotes`, `/ws/backtests/{id}`)
- 주요 엔드포인트: `POST /backtests` `GET /backtests/{id}` `GET /ohlcv` `POST /positions` `GET /portfolio/summary` `GET /signals/daily`(주문표)
- 에러는 problem+json(RFC 9457) 형식

## 인증 / 세션 모델 (공통)

- JWT Bearer + refresh 회전. WS는 접속 시 토큰 검증

# 11. 테스트 / QA 요구사항

## 반드시 검증해야 할 핵심 시나리오

1. **전략 로직 골든 테스트**: `trade_algorithm_final.md`의 수치 예시(그리드 68,950/67,900/66,850, 익절 69,984, 배분표 E=1.30→레버리지 30%+KODEX200 70% 등)를 고정 입력 대비 기대 출력으로 검증
2. 백테스트 look-ahead 부재: 신호일까지의 데이터만으로 익일 체결이 재현되는지
3. 레짐 상태 머신 전이(완충 포함) 전 케이스, 갭 필터·잔여예산 규칙
4. 백테스트→실전 전환 시 파라미터 보존

## 자동 테스트가 필요한 영역

- 전략 엔진(지표 계산·레짐·배분·주문표) 단위 테스트, 백테스트 엔진 회귀 테스트, API 계약 테스트, CI e2e(compose)

## 수동 QA가 필요한 영역
